# Requestman for macOS

独立的纯 AppKit macOS Web 调试工具。以规则组组织请求修改，每条修改包含请求、响应两条流程；主窗口固定显示请求修改，主内容区右上角的 `eyeglasses` 图标打开独立请求日志窗口，重复点击唤起已有窗口。环境按钮宽度为 90–140 pt，位于左侧栏开关右侧；启动按钮位于主内容区工具栏左端。环境管理收纳在设置中，设置顶部的“通用 / 环境管理”继续使用原生 `NSSegmentedControl`。界面依据 [设计稿](Docs/Design/README.md) 实现，浏览器扩展仍独立运行与发布。

代码职责与请求生命周期见 [捕获与规则执行架构](Docs/EngineArchitecture.md)。

请求日志窗口使用可接收键盘输入的非激活面板，采用普通窗口层级，不常驻置顶；保留加入全屏浏览器所在 Space 的配置，点击日志不会为了激活主窗口而切换桌面。窗口保持原来的最小尺寸 1100 × 680 pt。选中日志窗口后按 `⌃⌘F`（或使用“窗口 → 进入全屏”）进入自身的原生全屏，退出后恢复普通层级；非全屏时绿色按钮继续用于缩放。全屏空间中的拖动、焦点和恢复行为仍待真实 Mac 人工验收。

脚本 fetch 的 API、出口与取消语义见[异步脚本与辅助 HTTP](Docs/Design/async-scripts.md)。还未实现 WebSocket 消息修改、独立 HTTP Call 步骤、人工断点、自动持久化执行历史和透明应用接管。HTTPS 支持 HTTP/1.1 与 HTTP/2，两端保持同协议，协议不匹配直接失败，不转换或重试；证书绑定客户端仍可能拒绝调试证书。完整目标见 [产品设计](Docs/ProductDesign.md)。

所有捕获来自真实代理流量，首次启动不插入示例规则组和假记录。主导航栏用绿色播放图标启动、红色停止图标结束捕获；悬停提示与辅助功能标签根据通用设置说明当前启动方式或浏览器名称。全局模式先监听再接管系统 HTTP/HTTPS 代理；浏览器模式仅启动本地监听，并通过启动参数让所选浏览器的调试实例使用该代理，不改系统代理。两种捕获方式都不修改 Surge 配置或证书信任；证书引导是单独的用户操作。系统代理只接入遵循该设置的应用，不覆盖自行直连或 UDP 流量；浏览器模式是显式代理接入，不是按进程过滤网络流量。启动浏览器不代表已观察到浏览器流量。

## 手机接入

设置 → 通用选择“仅启动代理”，开启“允许局域网设备连接”，从主窗口启动捕获。三种启动方式均在局域网监听成功后显示标题栏右侧的手机图标。点击后按“准备网络 → 在手机上设置代理 → 安装并信任证书”三步操作，服务器明确标注为这台 Mac，端口使用实际监听值。iPhone / Android 在当前 Wi-Fi 中手动配置代理，安装证书后按各平台步骤信任。HTTP 上游配置统一适用于本机与手机流量。

日志中的设备来源内容和详情均可点击，通过原生 Popover 设置或清除别名；同一来源立即统一刷新，别名随工作区保存。设备按客户端 IP 识别，IP 改变后需要重新设置；旧日志缺少来源时，列表按该内容的空值设置展示，详情显示“未知设备”。证书绑定、不遵循代理的 App、蜂窝直连及 UDP 不在此接入方式的保证范围内。详细步骤和技术边界见[局域网手机抓取](Docs/Design/mobile-capture.md)。

日志右上角搜索框按最终显示的内容进行不区分大小写的包含匹配，包括各行内配置的字段和自定义空值文字。隐藏的缺失内容不参与搜索；设备来源内容还需开启局域网连接。应用布局或更新规则／设备名称后即时更新结果，搜索不受列宽造成的省略影响。保存当前日志沿用相同的搜索范围。

筛选表单在标题栏下方横跨日志窗口展开，保留约 0.2 秒高度动画；快速反向操作从当前高度继续，开启减少动态效果时直接切换。表单高度最多 320 pt，且不超过窗口内容高度的 45%，超出内容在表单内部滚动；调整窗口尺寸后重新计算，收起不重置条件。下方分类栏保持自身高度。

日志筛选配置底部可勾选“保存筛选项”，立即保存当前条件及后续修改，下次启动自动应用（包含搜索词、资源类型和反向匹配）。取消勾选清除已保存条件，当前筛选保留；重置在保存开启时同步保存空条件。

分类栏右侧的“显示选项”打开原生 AppKit 配置表单，按钮始终保持普通图标样式，不随自定义列配置高亮。上方整体预览展示所有配置列，空列也保留列标题；下方左侧直接增删列、调整列顺序，中间编辑列标题并编排各行和行内内容，右侧设置所选内容的字段、来源、对齐、空值行为和外观。两侧设置区固定宽度，中间列布局占满剩余空间。列数由左侧列列表控制；空值处理独立配置到每项内容。

编辑时先更新整体预览，点击“应用”后才更新日志并保存配置；“取消”放弃本次编辑。“恢复默认”只将表单草稿恢复为默认布局，仍需点击“应用”生效。字段配置无效时显示错误并禁用“应用”。

时间、状态码、请求方法、URL、规则组、规则、设备来源、耗时、重放与错误信息，以及 Header、查询参数、主机和路径均可放入任意列和行。同一行可放多项内容，也可将规则组放在第一行、规则放在第二行；选择“规则组与规则”则整体显示。水平对齐和行内垂直对齐使用原生图标分段控件，并提供悬停提示与辅助功能名称。

显示选项中的按钮、下拉框和分段控件使用系统样式与固有尺寸；macOS 26+ 的按钮通过原生 `.glass` 样式配置胶囊或圆形，下拉框和分段控件使用原生胶囊形状，旧系统沿用默认样式。对齐分段等分占满标签右侧空间；macOS 27+ 明确使用原生玻璃选择样式。列列表与内容布局表格使用白色圆角边框，选中列使用浅蓝圆角背景，编辑其他控件时继续保留；字段按钮直接起拖，独立业务状态记录选中项并显示蓝底白字，原生按钮仍使用瞬时按压类型；按钮和所在 cell 不绘制焦点环，整行拖动仅从左侧柄或行标签发起。起拖前由普通原生按钮 cell 在独立透明位图中同步生成拖拽图像，按当前屏幕缩放比例保留清晰度，并让绘制坐标方向与原生按钮一致；不修改或重绘源按钮，各字段使用相同的普通拖拽图像，选中项、辅助功能状态和草稿保持不变。拖拽图像沿用鼠标按下时的所抓位置，由稳定的窗口内容宿主发起。拖动期间只预览布局：源字段隐藏与同尺寸占位在一次排版中更新，目标位置显示同宽的半透明原生按钮占位，邻近字段用约 0.12 秒动画挪开；开启减少动态效果时直接挪位。插入位置按所抓偏移与其他字段的稳定顺序和宽度计算，不依赖占位或动画中的位置，宽首项也使用相同的双向插槽规则。同一位置重复悬停不会重启动画，首项和原位放下也有效；成功放下后才更新草稿，原位保持原顺序。移到内容区左右边缘时自动横向滚动，离开或无效目标会清除目标占位；取消、结束拖动、重新加载或切换列时恢复源字段布局。拖动列或整行时，指针在目标行的上半部放到其前面，下半部放到其后面。日志与整体预览的只读内容默认使用原生 `NSTextField`；圆角标签和胶囊共用同一种原生按钮样式及内边距，仅圆角形状不同；切换呈现方式保留字段文字颜色。设备来源使用相同的普通原生胶囊按钮。方法与状态码默认保留系统语义色和必要字体，长文本省略时保留完整悬停提示与辅助功能内容。

右侧“空值”下方提供所选内容的“外观”设置，可选择纯文字、圆角标签、胶囊、圆角边框或胶囊边框，配置字体、字重和省略位置。选择圆角标签或胶囊时，背景颜色可选“自定义”或“跟随文本”；设备来源的胶囊同样可设置。自定义提供原生取色器及“恢复默认”按钮；跟随文本使用当前文字颜色，并可用原生滑块调整背景透明度（0–100%，默认 85%；0% 不透明，100% 完全透明），旁边显示当前百分比，拖动即时更新预览，以淡色底衬托文字。颜色模式、透明度和自定义颜色独立保存到当前内容项，预览与实际日志共用原生 `NSBox.fillColor` 绘制显式背景，避免按钮在窗口失焦时将底色显示为灰色；未设自定义颜色时沿用原生按钮的系统背景。跟随文本的底色随方法／状态着色和行选中文字同步变化；切回纯文字、切换字段或颜色模式时保留设置。旧配置继续采用已有自定义颜色或系统背景，自定义模式下恢复默认采用系统背景。圆角边框和胶囊边框使用透明背景，可调整边框粗细（0.5–8 pt，默认 1 pt）；边框颜色默认“跟随文本”，随方法／状态着色和行选中文字变化，也可选择“自定义”并用系统取色器设色。切换颜色模式或呈现方式会保留自定义颜色和粗细；每个内容项独立保存，预览和日志共用设置。选择“不省略”时，纯文字、圆角标签、胶囊、两种边框及设备内容按实际分配宽度自动换行并增加行高，完整显示全文；没有空格的长 URL 也按字符换行。字段专属选项包括方法／状态着色、状态说明与异常强调、URL 主机强调、时间精度、耗时单位与小数精度及慢请求阈值、规则分隔符，以及 Header／查询参数的重复值单行或多行显示与数量提示。修改即时更新整体预览，点击“应用”后用于实际日志；切换字段保留该内容的外观配置，旧布局缺少配置时使用兼容默认值，原先保存的“自动”呈现按纯文字显示。显示格式不改写原始捕获数据，搜索沿用最终显示的完整文本。

内容没有值时默认不显示，也可选择自定义文字并填写默认值。整行没有可显示的内容时收起该行；每个单元格实际可见的行整体垂直居中。重复值选择多行显示时，实际展开多行并增加表格行高；规则换行分隔同样生效。行高按同条记录各列在实际宽度下度量的内容高度调整，保留原有最小高度；修改列宽或外观后重新计算。

Header 支持请求和响应的原始／处理后阶段，查询参数、URL、主机、路径和方法只提供请求阶段，状态码只提供响应阶段，不回退到其他来源。Header 名称忽略大小写，查询参数名区分大小写；重复值可悬停逐行查看。日志表头仍可拖动调整列顺序和列宽，拖动结果自动保存；应用表单后保存布局和列身份，旧显示开关、额外字段和合并关系自动迁移到新的行布局。设备来源内容仅在允许局域网连接时显示。

## HTTP/2

HTTPS 解密连接通过 ALPN 接入 HTTP/2，支持同连接并发请求、现有双向规则与 Mock、SSE、单流取消和同协议重放；上游只协商客户端协议，不降级或跨协议转换。请求详情分别显示客户端与上游版本，日志文件保留协议和 trailers。明文 h2c 与 WebSocket Extended CONNECT 暂不支持。实现和验证范围见 [HTTP/2 捕获与修改](Docs/Design/http2.md)。

## 规则命中通知

全局接管和仅启动浏览器两种捕获模式都支持 macOS 本地通知。首次启动捕获时请求通知权限；允许后，匹配到规则即发送标题为“规则命中”的无声通知，正文只列出规则名称。拒绝授权不会阻止捕获，可在系统设置 → 通知 → Requestman 中重新开启。Requestman 位于前台时也允许展示横幅，最终展示仍遵循系统通知设置和专注模式。

每轮从首次命中开始固定聚合 3 秒：首条立即提交，不等待窗口结束；后续不足 3 秒的命中更新同一条通知，规则按 ID 去重、按首次命中顺序逐行列出。达到或超过 3 秒后的首次命中新建通知并开始下一轮，不延长上一轮、不等待空闲。例如 0 秒命中 A、2 秒命中 B、3.2 秒命中 C，第一条为 A/B，第二条为 C。窗口到期不额外发通知，也不删除已送达通知。暂停或清空请求日志不影响通知；停止或重启监听清空待发送内容和当前聚合状态。系统可能在更新时再次提示，长正文可能被横幅截断。

## 键盘操作

工作区命令位于原生「文件 / 编辑 / 显示 / 捕获」菜单，菜单和按钮提示显示快捷键。「显示」菜单将「规则配置」和「请求日志」放在同一组，与其他显示操作用分隔线隔开。应用使用独立窗口，关闭系统自动窗口标签功能，不提供标签栏与标签页概览菜单。命令作用于当前前台的请求修改或日志窗口，设置窗口和模态面板不会触发后台工作区操作；不可用的命令自动禁用。

| 复制侧栏选中项 | `⌘D` |
| 重命名侧栏选中项 | `Return` |
| 删除当前列表选中项 | `⌘Delete` |
| 启用 / 停用当前列表选中项 | `⌘⇧L` |
| 复制选中请求完整 URL | `⌘⇧C` |
| 复制选中原始请求为 cURL | `⌘⌥C` |

暂停记录、清空、筛选及请求复制仅在日志页可用；URL 截断或请求不完整时沿用导出的禁用条件。规则组 / 规则的复制和重命名要求侧栏获得焦点，删除和启停要求侧栏或步骤列表获得焦点；编辑文本不会误操作列表。新请求使用侧栏当前规则组，创建后选中名称；新规则组打开名称输入面板。

`Tab / ⇧Tab` 使用原生焦点导航，列表用方向键选择，规则组用左右键展开、折叠。环境选择器打开后聚焦搜索，方向键仅移动候选项，回车确认，`Esc` 关闭并返回原焦点。配置继续自动保存。

规则侧栏支持原生拖拽排序：拖动规则组会整体移动，拖动规则可在组内排序或移入其他组，放到组名上会追加到该组末尾。搜索期间也可排序，隐藏规则保留相对顺序。顺序自动保存，并决定多个规则同时匹配时的优先级。

## 手动接入

1. 打开 [Requestman.xcodeproj](Requestman.xcodeproj)，使用共享的 `Requestman` scheme。开发环境要求 Swift 6.2+，部署目标 macOS 14.0。
2. 点击侧栏底部加号，在菜单中选择“添加规则”或“添加规则组”。添加请求时使用当前请求所属规则组，未选中请求时使用第一个规则组，没有规则组时自动创建；新请求会被选中并展开所属规则组，同时清空搜索。添加规则组沿用创建规则组及首条请求的流程。配置请求修改，例如 URL 通配符 `http://localhost:3000/*`，添加请求 Header 或静态 Mock。匹配采用规则组顺序中的首个启用流程，空匹配值不匹配；多个匹配流程不叠加执行。
3. 从菜单栏“Requestman → 设置…”（`⌘,`）打开“环境管理”创建环境，填入 `apiKey`、`cookie` 等变量，选择字符串、数值、布尔、数组或对象类型（非字符串值使用 JSON 格式；布尔为 `true` / `false`），在步骤中引用 `{{$env.apiKey}}`，使用标题栏原生环境下拉框快速切换整组变量。配置停止编辑约 350 ms 后保存并应用；已开始的请求继续使用原快照。
4. 在设置 →“通用”选择“全局接管”或“仅启动浏览器”，并在带图标的下拉框中选择已安装的 Chromium 浏览器。点击主导航栏启动按钮：全局模式按 macOS 提示授权，让系统 HTTP/HTTPS 代理指向默认 `127.0.0.1:9090`；浏览器模式通过参数打开所选浏览器的调试窗口。首次使用默认全局接管，启动方式和浏览器选择会记住；运行中修改用于下次启动。设置内没有单独启动按钮。
5. 打开本地 HTTP 开发页面。请求日志中确认命中的规则组、步骤、目标与响应。Chrome Network 的请求仍是浏览器发出的内容；HTTP 响应是代理处理后的结果。
6. 点击导航栏停止按钮或正常退出：全局会话先恢复原系统代理，再关闭监听和现有隧道；浏览器会话只关闭监听和隧道。全局恢复失败会保留监听，显示错误供重试，并暂缓退出。停止按实际运行模式执行，不受下次启动偏好影响。专用调试浏览器窗口和标签页会保留，停止期间通过该代理的新请求会失败；在同一 Requestman 运行期间，使用相同浏览器和端口再次启动时，恢复监听并激活原实例，不新开空白窗口。失败页面可能需要刷新。

本地代理端口和上游配置均在设置 →“通用”中，不出现在主工作区。配置了上游时不会失败后静默改走其他出口；不使用 HTTP 上游时仅沿用系统路由，仍可能经过其他网络软件的增强模式。上游认证暂未实现。监听期间也可编辑本地端口和上游配置，停止输入约 350 ms 后自动应用，无需手动启停。上游变更用于新连接，现有请求与 CONNECT 隧道继续使用原配置；端口变更自动切换监听并关闭现有连接，全局模式同步系统代理，浏览器模式不改系统代理，优先复用当前会话浏览器在新端口上仍存活的调试实例，没有可复用实例时才打开新窗口。旧浏览器窗口仍固定使用旧端口，不自动关闭。无效配置不打断监听；新端口启动失败会尝试恢复原配置与原模式，设置页显示应用错误。

启用 HTTP 上游时，两种启动方式都会先检查上游地址的 TCP 连接，最多等待 3 秒。失败后可选择“关闭上游并启动”（关闭并保存上游设置）、“继续使用上游”（保留配置启动）或“取消启动”。选择前不创建监听、不切换系统代理。该检查不访问外部测试网站，只确认端口可连接，不验证代理认证、协议能力或目标站点可达性。

使用 Surge 时，先启用“使用 HTTP 上游代理”并填写 Surge 的 HTTP 监听地址与端口，再开始捕获。流量路径为“应用 → Requestman → Surge → 服务端”；默认填写值 `127.0.0.1:6152` 不代表已检测到 Surge。监听期间避免让 Surge 重新接管系统代理，否则遵循系统代理的应用可能绕过 Requestman。

接管覆盖当前网络位置中已有且已启用代理协议的网络服务，包括未连线的 Wi-Fi/以太网服务。接管时临时禁用 PAC、自动代理发现和 SOCKS，并清空绕过列表；停止时按字段组恢复原值，保留用户或其他工具在监听期间修改的字段组。切换网络位置或新增服务后，需要停止并重新开始捕获。原配置保存在 `~/Library/Application Support/Requestman/system-proxy-recovery.plist`，仅当前用户可读写。强制退出或崩溃后无法立即恢复，重新打开 Requestman 会尝试恢复；恢复成功前不覆盖旧记录。

浏览器通过 NSWorkspace 启动。发现范围包括系统注册的 HTTP/HTTPS 处理应用与系统、用户的 Applications 目录，结合 HTML 文档声明和 Chromium 框架资源识别浏览器，排除普通网页容器、Electron 和 CEF 应用；过滤更新缓存与废纸篓副本，按 Bundle ID 去重；不同发行渠道分别列出，同名应用显示所在目录。浏览器选择保存在本机偏好设置中。Google Chrome 继续使用 `~/Library/Application Support/Requestman/Chrome/port-<端口>`，其他浏览器使用 `~/Library/Application Support/Requestman/Browsers/<编码后的 Bundle ID>/port-<端口>`，避免共享不同产品的调试数据。启动器在内存中按应用路径、Bundle ID 对应的数据目录和端口保留进程记录，独立于捕获会话；存活时只激活原实例，已退出时沿用原数据目录重新启动，保留 Cookie 等数据，但不额外保证恢复已关闭的标签页。Requestman 重启后不恢复进程记录。启动前重新校验所选应用，启动期间禁止重复操作，失败时显示具体浏览器名称；仅回滚本次新建的监听。发现成功不等同于各浏览器均已验证支持全部启动参数，Arc、Dia 等衍生浏览器的配置目录、代理参数和实际流量仍需逐个运行验收。启动参数依据 Chromium 的 [用户数据目录](https://chromium.googlesource.com/chromium/src/+/HEAD/docs/user_data_dir.md) 和 [代理配置](https://chromium.googlesource.com/chromium/src/+/HEAD/net/docs/proxy.md) 说明。

设置 →“通用”的“HTTPS 证书”分组提供“设置证书…”。点击后自动检查已有证书，依次生成本机 CA、安装到默认钥匙串并请求当前用户的 SSL 信任；仅需响应 macOS 授权提示。取消会保留已完成步骤，可再次点击继续；重复操作复用同一证书，不重复生成。引导可查看证书名称、有效期与 SHA-256 指纹，失败时提供重试和“钥匙串访问”入口。完成后证书状态显示“已完成配置”；重新打开通用页或返回应用时会只读检查证书状态，失效后恢复设置入口。证书就绪后新 CONNECT 连接按照“HTTPS 解密”设置处理，无需重新启停监听。已有透传隧道不能就地解密，需刷新页面或重新打开调试浏览器建立新连接；旧日志不会补全成明文。

“HTTPS 解密”分组提供“解密所有请求”开关，默认开启，旧工作区保持原有行为。关闭后只解密“指定域名”列表中的 HTTPS 连接，空列表表示全部透传。多个域名用英文分号 `;` 分隔，例如 `api.example.com; *.example.com`，处理时自动去掉每个域名首尾的空白；`api.example.com` 精确匹配，`*.example.com` 匹配任意层级子域名，但不包含 `example.com` 本身，两者需要时分别填写。域名忽略大小写和末尾的一个点；国际化域名使用 Punycode，不填写协议、端口或路径。格式错误时保留输入并提示未保存，继续使用上次有效列表。开关开启时保留列表供下次使用。

解密范围独立于请求修改规则，停止输入约 350 ms 后保存并用于新连接；不重启代理或切换已有连接。未命中的 HTTPS 连接不签发调试证书、不执行 HTTP 修改规则、不采集 Header/Body，只保留 CONNECT 隧道记录，仍经配置的出站方式转发。普通 HTTP 请求保持现有处理方式。解密设置包含在全量备份中，导入单个规则组或请求不覆盖它。

CA 私钥仅保存在本机文件型钥匙串，禁止导出，由钥匙串锁与访问控制保护，不写入应用配置、临时文件或日志。信任限制为当前用户的 SSL 用途，使用 [Security 原生授权接口](https://developer.apple.com/documentation/security/sectrustsettingssettrustsettings(_:_:_:))，不使用提权脚本。信任完成后通过内存测试证书与系统 SSL 策略验证，不注入自定义信任锚点；[Chromium 会读取默认钥匙串和系统钥匙串中的 SSL 信任](https://chromium.googlesource.com/chromium/src/+/main/net/data/ssl/chrome_root_store/faq.md)。系统授权界面与实际浏览器信任仍需人工运行验收。

授权只在用户主动配置证书时发生，配置阶段为当前应用建立持久的 CA 签名权限，新权限描述为“Requestman HTTPS 调试 CA”。已有证书复用原私钥与信任，修复签名权限不重新生成 CA。完成前会在禁止弹窗的条件下复核签名能力和实际 SSL 信任；启动、返回前台、状态检查及 HTTPS 解密均禁止钥匙串授权弹窗。钥匙串锁定或应用签名变化导致授权不可用时，在通用设置中提示点击“设置证书…”重新授权，不自动重弹。

启动及返回前台只读取现有 CA 状态，不尝试迁移或修改私钥 ACL；禁止弹窗的检查发现授权不可用时，仅显示“设置证书…”入口。只有用户主动配置时才修复签名授权，复用原 CA 和已有信任；不能绕过应用身份变化后的系统授权。

在系统中删除证书或私钥后，本地可能仍保留公开 CA 文件。检测到私钥缺失时，证书设置显示“重新生成证书”；点击后仅清理对应旧 CA 的当前用户信任与默认钥匙串证书，将旧公开文件移入废纸篓，再生成、安装并信任新 CA。若私钥仍在则复用并重新安装原证书；钥匙串锁定、授权被拒或存在其他同名证书时不自动替换。取消或保存失败后可继续设置。

读取已有 CA 时从公开证书取得公钥，`KeychainSigningKey` 仅通过 `SecKeyCreateSignature` 签名，并校验实际签名与证书公钥匹配；运行期不再从钥匙串导出公钥，私钥序列化明确拒绝。文件型钥匙串的交互开关属于进程级状态，由统一同步锁覆盖配置、状态读取和签名，退出作用域后恢复；这不替代应用签名身份与钥匙串 ACL。实际系统弹窗、重新启动和重新编译后的行为仍需 App 验收。

TLS 传输使用 Apple `swift-nio-ssl`。按目标域名/IP 签发短期站点证书，SAN 包含 DNS 或 IP，最多缓存 128 个站点且不晚于 CA 到期；站点私钥只保留在内存中。CA 材料与实际信任检查结果最多复用 5 秒，避免并发 CONNECT 重复读钥匙串和签名验证；状态刷新、证书设置操作与应用重新激活会触发重新检查，外部信任修改最迟在缓存到期后的新 CONNECT 生效。上游证书交给 macOS Security 校验信任链、有效期及主机名，不关闭校验，也不因失败回退到明文或其他出口。系统验证禁用网络补取，避免经系统代理递归；站点应发送完整中间证书链。

## 行为与资源边界

通用设置最底部的“清除工作区…”会先弹出二次确认，默认选择“取消”。工作区因旧版本或文件损坏而读取失败时，此按钮仍可使用；加载或其他操作进行中保持禁用。确认后停止捕获并恢复系统代理，清空所有规则组、规则、环境和请求日志，将代理与 HTTPS 解密配置恢复默认，同时重置日志筛选和暂停状态。证书、浏览器数据、启动方式、浏览器选择及窗口/列宽等应用偏好保留。停止捕获或保存空工作区失败时保留原工作区数据并显示错误；停止成功后若保存失败，捕获保持停止。

- Body 未被替换时以二进制块流式透传，同时旁路保留有界预览；网络线程不解压或解析 JSON。静态 Body 替换不等待完整原 Body；转发期间仍会消费原流以完成 HTTP 消息。
- `Content-Length`、传输分块、Host 与逐跳头由代理维护；不能通过 Header 步骤注入矛盾的报文边界。替换 Body 清除原编码与内容校验字段。重定向返回 3xx，内部 URL 改写不向客户端返回 3xx。
- HTTP/1.1 支持同一客户端连接上的顺序请求；目标和出口相同时复用上游 TCP/TLS 连接。客户端要求关闭、错误、Mock 或重定向响应会关闭连接；不支持流水线请求或跨客户端连接池。HTTP 请求事务与流程预览不设总时限；等待首个请求和 CONNECT 建立仍限时 30 秒，HTTP keep-alive 空闲 30 秒关闭，透传 CONNECT 空闲读超时 120 秒。SSE 长连接按上游响应类型进入持续捕获路径。
- 活跃连接、预读队列、步骤和记录数量仍有上限；UI 和磁盘保存不阻塞转发。详见 [性能边界](Docs/Performance.md)。
- 记录保留最近 500 条；原始/最终请求和响应完整采集 Body，URL、Header 名称、数量和值不截断，不设置 Body 尺寸或共享载荷预算。快照不落盘，关闭应用即丢失。所有 Header（包括 Authorization、Proxy-Authorization、Cookie、Set-Cookie 和 X-API-Key）均保留原值，可查看、比较和复制；环境变量编辑器直接显示值。URL、Body 与自定义 Header 是本机调试数据。暂停记录不会停止流程或网络。
- 工作区位于 `~/Library/Application Support/Requestman/workspace.json`，目录权限 0700、文件权限 0600。环境值目前存于这个本地文件，尚未迁移到 Keychain。加载失败时禁用编辑，避免覆盖原文件。

请求日志筛选、Header 匹配语义和命中规则展示见 [筛选设计](Docs/Design/request-log-filters.md)。

## 从日志创建 Mock

日志右键选择“Mock 当前请求”，以原始请求方法和完整 URL（含查询参数）建立精确匹配。请求流程预填方法、完整 URL、原始请求 Body 和原始请求 Header；不生成“返回静态数据”，请求继续转发上游。有完整上游原始响应时，响应流程依次预填原始状态码、原始 Body 和原始 Header，使用服务器返回的快照，不使用被规则修改后的最终响应。Header 直接展示捕获名称和值，所有条目的修改方法统一使用“修改”，保留捕获值和条目顺序；执行沿用现有修改语义：只更新已有同名项，缺失时跳过。Host、Content-Length 和连接级字段交给代理重新生成。

创建后跳转到规则编辑页并选中新规则；有既有匹配规则时，新规则插入该启用规则组的首位，否则放入当前规则所属的启用规则组或首个启用规则组，没有可用规则组时新建。所有数据来自打开右键菜单时的原始请求快照，不受新增或清空日志影响。未解密隧道或原始请求未完整采集时禁用入口并说明原因；原始响应缺失或不完整时仍可创建请求步骤，但响应阶段留空，不伪造状态码或正文。

生成的步骤默认关闭“解析模板变量”，两阶段 Body 和 Header 中的 `{{…}}` 保留原文；需要动态变量时可在步骤详情开启。gzip/deflate 正文在后台解码，移除相应编码与内容校验字段；UTF-8 文本可直接编辑，二进制、其他字符编码或不能解压的内容以 Base64 保存原始字节，详情显示“Body · Base64”。不能解码时保留原 Content-Encoding。保存与配置导出包含这些正文，不依赖原日志继续存在。Body 编辑区无论是否启用模板解析，都裁切行号栏，限制在输入框内。

## 请求详情

请求修改与请求日志使用各自的 AppKit `NSSplitViewController`；主窗口承载左侧规则组栏、规则内容和步骤 Inspector，日志窗口承载请求列表和请求 Inspector；两侧使用系统侧栏角色与全高材质。选中新日志后展开详情，再次点击当前日志切换详情展开／收起，保留选中项和各 Tab 浏览状态；宽度默认 520 pt，可在 400–760 pt 调整。窗口只有一条原生 `NSToolbar`：右上角的原生 `NSToolbarItem` 显式连接分栏控制器的 `toggleInspector` 动作，采用系统默认按钮外观；收起、展开后都保留，未选中有效内容时禁用；请求修改页复用该按钮控制步骤详情。列表不另设第二个展开按钮。“请求详情”标题仅在展开时显示，位于跟随右栏边界的工具栏分隔线之后，左对齐，使用系统 `.title2` 对应字号和 semibold 字重，不添加边框或额外玻璃背景。手动收起保留选择及各 Tab 浏览状态。

整个窗口及详情均不设底部状态栏。详情上方保留方向、数量、“仅显示变更”和内容提示，数据区域延伸至底部操作区上方。底部只保留搜索和 JSON 原始数据切换，横向 12 pt、纵向 10 pt 留白与左栏一致。侧栏使用系统背景，字段树和原始数据视图不再铺设独立白底。此轮原生窗口布局和外观仍待真实 App 运行验收。

摘要顶部直接以 URL 为标题，单行保留首尾、中间省略，悬停显示已记录的完整地址。URL 右侧提供原生圆形“复制完整 URL”按钮；记录已截断时禁用复制，并通过按钮提示说明原因。摘要保留方法、状态码和耗时；方法标签和状态码复用列表样式及着色。查询参数作为请求头后的独立 Tab 展示原始/最终查询项，不混入请求体。命中规则时以 14 pt 原生路径控件显示“规则组 > 规则”，点击直接打开对应请求修改，已删除目标禁用跳转；未命中时隐藏此行。

“修改前 / 修改后 / 修改对比”已收进详情更多菜单的“显示选项”子菜单，通过原生勾选项切换，默认“修改对比”。整个 Inspector 共用一份显示模式，在五个内容 Tab、侧栏收起重开及选择不同记录时保持。

更多菜单位于展开侧栏的原生工具栏中、收起按钮左侧，侧栏收起时隐藏。菜单使用 `NSMenuToolbarItem`，依次分组提供“重放 / 重新发送请求…”、“复制”子菜单和“显示选项”子菜单。“复制”子菜单包含“复制 URL”、随当前 Tab 变化的内容复制项、“复制原始请求 cURL”和“复制修改后请求 cURL”。日志右键菜单提供相同重放与复制子菜单（不含详情 Tab 内容项），并单独保留“Mock 当前请求”。

重放基于原始请求，使用当前规则和上游配置，结果显示为新日志；实际发送需要捕获正在运行。“重新发送请求…”在捕获停止时也可打开原生编辑窗口，可修改方法、URL、请求头与正文；发送前取消不产生请求，发送中取消会终止此次提交。UTF-8 文本直接编辑，压缩或二进制正文以 Base64 保留，Host 和长度等连接字段自动生成。WebSocket、加密隧道或未完整采集的请求禁用重放并说明原因。复制项继续依据各自快照的完整性决定可用性。

内容只有一排“请求头 / 查询参数 / 请求体 / 响应头 / 响应体”原生 `NSSegmentedControl`，macOS 26+ 通过控件自身的 `borderShape = .capsule` 使用原生胶囊外观，旧系统保留默认外观，不额外包装玻璃背景；五个 Tab 按标签自然宽度比例分配可用空间，以原生完整尺寸显示，填满整行；当前内容的复制入口移至更多 → 复制，加载中或无可复制数据时禁用。URL 和字段右侧的快捷复制按钮保留。各 Tab 独立保留搜索、原始数据格式、滚动和展开状态。底部格式切换按钮在 macOS 26+ 使用控件自身的 `.glass` 样式，不叠加玻璃容器；`NSSearchField` 使用大号系统搜索外观，不额外包装玻璃。请求体、响应体的 JSON 树提供“原始数据”按钮，用只读 `NSTextView` 查看保留原有缩进、换行和字段顺序的文本；按钮随之变为“树形视图”，可切回字段树。此按钮只切换树形/原始数据格式，不改变当前显示模式；非 JSON 内容直接显示文本或十六进制，不提供无效切换。原始响应指服务器返回，最终响应指代理发给客户端；Mock 无服务器原始响应，不伪造空对象。Header 和 JSON 字段只用背景区分增删改，不增加“已修改”标签。鼠标悬停行右侧的复制按钮以 0.15 秒淡入淡出（减少动态效果时直接切换），字段仅复制其值，容器复制整个 JSON 子树（搜索后仍复制完整子树）；也支持右键和 ⌘C。

完整 gzip / deflate 内容仅在查看时后台解压，不设置输出尺寸或编码层数上限；JSON 解析不设置应用层大小、深度和节点数上限，继续使用 Foundation JSON 解析器。未知编码、二进制或不合法 JSON 通过源码/十六进制查看并注明原因；不把未采集或断流当作空 Body。具体设计和验收见 [请求详情设计](Docs/Design/request-inspector.md)。

字段值为字符串时，悬停会后台尝试解析为 JSON。解析成功后，复制按钮旁显示“查看 JSON”图标；点击用系统 Popover 和相同字段树查看，支持继续展开、复制及检查嵌套的 JSON 字符串。原字段类型和复制内容不变；普通文本和未完整采集的 Header 不显示预览图标。

## 工程与验证

App 的 Bundle ID 为 `com.muirr.requestman.macos`，Debug 与 Release 共用 `Configuration/Base.xcconfig` 中的配置。

主图标使用 [AppIcon.icon](Requestman/Resources/AppIcon.icon)，要求 Xcode 26 或更新版本处理 Icon Composer 资源。蓝色渐变网格背景与橙白请求/响应图形分层保存，圆角与材质由系统生成；`Base.xcconfig` 指定图标名，工程资源阶段编译该文档。最低部署版本仍为 macOS 14，旧系统位图由 Xcode 的图标编译流程生成。素材、预览与验证方式见[图标说明](Docs/Design/app-icon.md)。

证书模块测试覆盖 CA 格式与签名、内存 SecKey 签名、安装与信任幂等、授权取消重试、错误状态、文件恢复、最终信任复核与重复启动保护。测试只使用内存材料和替身；实际 Security 校验只读验证未安装的随机 CA 不可信，不写入本机钥匙串或信任设置。真实回环 TLS 测试覆盖完整 URL/方法/Header、双向修改、Mock、HTTP 上游 CONNECT、首包 ClientHello 保留，以及不受信/错域名服务器证书的拒绝。测试专用锚点仅注入到内存验证实例，不写入系统信任。新增依赖为 Apple `swift-certificates` 和 `swift-nio-ssl`，版本锁定在 Package.resolved，分发时需包含其及传递依赖的许可证。

宿主通过 `CaptureService` 访问实现；`RequestmanCore` 保存模型、动作与资源契约，`RequestmanProxy` 使用 SwiftNIO 处理真实连接。依赖版本记录在 [Package.resolved](Packages/RequestmanCore/Package.resolved)。

开发 HTTPS 解密时需使用稳定的 App 签名：复制 [Signing.local.xcconfig.example](Configuration/Signing.local.xcconfig.example) 为同目录的 `Signing.local.xcconfig`，填写开发团队 ID；本机配置已被 Git 忽略，并由 `Base.xcconfig` 引入。临时（ad hoc / Sign to Run Locally）签名以构建哈希标识 App，重新编译会使旧 CA 私钥授权失效，不能保证跨构建免授权。Bundle ID 也是钥匙串识别应用的签名条件之一：由旧标识 `com.requestman.macos` 切换为 `com.muirr.requestman.macos` 后，即使开发证书不变，也可能需要重新授权一次。固定 Bundle ID、开发团队和签名证书后，打开一次“设置证书…”为现有 CA 授权，无需重新生成 CA；配置阶段会实际请求一次签名，让系统处理签名身份变化产生的授权，再进行禁止弹窗的最终复核。实际重新编译、重启后的钥匙串行为仍须人工验收。

Debug 使用 `ONLY_ACTIVE_ARCH=YES`，使宿主与 Swift Package 都面向当前运行目标的架构；Release 保留 `ONLY_ACTIVE_ARCH=NO`。不要仅让 Debug 宿主额外编译另一架构，否则可能在依赖只有 arm64 模块时出现 x86_64 的 `Unable to resolve module dependency`。工程检查脚本包含此配置校验；独立包的测试和源码类型检查不能替代 Xcode 工程构建验收。

## AppKit 界面

应用入口、主窗口、设置、环境、请求编辑、请求日志和全部弹层均由 AppKit 实现。保留现有三栏宽度、工具栏顺序、步骤卡片、分组设置及请求详情布局；Observation 仅用于模型变更追踪，不承载界面。窗口直接约束分栏和各页，避免跨框架尺寸协商。`python3 Scripts/check-native-sources.py --typecheck` 检查工程引用、纯 AppKit 约束和 Swift 6 类型；各 `check-*-ui.py` 与既有详情/分栏脚本运行隐藏窗口回归，不构建或启动完整 App。

请求阶段支持“修改查询参数”（逐条添加、修改或删除，修改与删除支持名称匹配规则，自动 URL 编码）和“替换 URL 字符串”（多个配置区块按顺序执行，单行查找，区分大小写，替换整个 URL 中全部原文匹配）。两项支持动态模板并按步骤顺序执行，详见[请求修改配置](Docs/Design/request-modification.md#url-修改步骤)。

## 规则组树与导入导出

菜单栏“文件”在新建操作下方单独分组提供“导入规则…”和“导出全部规则…”。导出全部规则保存当前所有规则组（包括空组）、组内规则及完整匹配条件和双向步骤，保留原有顺序、图标和启用状态。该文件只包含规则配置。导入规则支持单条、整组、全部规则和完整备份文件，统一将规则组追加到已有数据下方，不覆盖环境、代理或应用偏好；单条规则新建名为“导入 yyyy/MM/dd HH:mm:ss”的规则组，使用导入时的本地日期时间。每次导入重新生成规则组、规则和后代 ID。

文件夹与请求修改行统一为 30 pt，子项仅显示名称，名称左边缘与文件夹名称对齐。单击选择，双击文件夹整行或单击原生箭头展开/收起；左右键保留原生展开行为，展开箭头与行变化由 AppKit 管理，双击使用 180 ms 原生动画，减少动态效果时即时切换。保留当前流程和会话内展开状态。搜索与添加保持在底部。数量与更多按钮共用行尾位置：平时显示数量，悬停、键盘选中或菜单打开时切换为更多按钮，名称位置保持不变；右键菜单保持可用。未选中行悬停显示浅灰背景，以 Core Animation 在移入 120 ms、移出 160 ms 内淡入淡出，减少动态效果时即时切换。系统选中背景优先。“修改图标”提供六列、48 个候选的原生图标网格，仅显示预览，名称通过悬停提示和辅助功能提供。规则组菜单提供添加请求修改、整组启用/禁用、复制、重命名、图标选择、导出整组及删除；请求修改菜单提供启用/禁用、重命名、复制、导出及删除。规则组菜单的“全部禁用／全部启用”批量设置组内每条请求修改，规则组自身没有启用状态。禁用规则的整行内容以 45% 透明度显示，并保留停用标记，更多菜单仍可使用；规则组本身保持正常外观。

设置 → 通用 → 导入导出支持 `.requestman.json` 文件。全量导出包含所有规则组、请求修改的完整匹配条件和双向步骤内容、规则组图标及每条规则的启用状态、环境变量和当前环境、代理配置，以及应用持久化偏好（启动方式、浏览器选择、请求日志列宽等）。证书、公私钥与信任、系统代理恢复日志和浏览器调试配置目录不随备份迁移；请求日志不包含在配置备份内，可通过文件菜单单独保存为日志 JSON。

设置页的导入入口接受单条、整组、全部规则与全量备份文件。导入会追加新的规则组树，并为规则组、请求修改与步骤生成新 ID；重复导入不会替换已有请求。单条文件仅含该请求及所属规则组的信息，不携带其他请求、环境或偏好。整组文件仅含所选规则组。在设置页导入全量备份文件时，除追加规则组外，还会覆盖环境、当前环境、代理配置和整个应用偏好域；已显示的日志表格会立即恢复导入列宽。启动方式与浏览器选择仍遵循下次启动生效的既有约定，代理连接配置按原有规则应用。文件先完整验证，再保存工作区；文件版本不支持、损坏或工作区写入失败时不应用导入数据。

Body 与脚本输入使用独立 [RequestmanEditor](Packages/RequestmanEditor/README.md) 组件，组合 CodeEditTextView、HighlighterSwift 与复用的 MIT 行号栏；不自行实现文本布局或语法着色。

## SSE 与 WebSocket

支持 SSE 实时事件记录和 ws/wss 基础消息观察。引擎根据上游原始响应 Content-Type 自动识别 SSE，无需勾选开关；识别后替换响应 Body 会取消上游并生成替代响应。编辑页已移除 SSE 复选框，已有 Header 步骤保留，配置标记及手动添加 Header 不触发普通响应的 SSE 转换。事件与消息按页从会话临时文件读取，支持协议和活动连接筛选。WebSocket 首版不协商压缩扩展，逐事件/消息修改尚未实现。协议、存储与验证边界见 [持续捕获](Docs/Design/streaming-capture.md)。

## 保存与打开日志

请求日志右键提供“保存当前请求会话…”。“文件 → 保存当前日志…”（⌘S）保存当前搜索和筛选匹配的全部记录；“文件 → 打开日志文件…”（⌘O）在独立日志窗口打开文件，顶部可“返回实时日志”，捕获继续在后台记录。

默认扩展名为 `.requestmanlog.json`，文件内含版本与中文字段说明。文本 Body 直接阅读，二进制使用 Base64，gzip / deflate 可解码文本另附阅读副本。原始/修改后的请求响应、重复 Header、执行结果和 SSE/WS 已记录内容均保留。打开不自动发送请求，未完成连接保留保存时状态。详见[保存日志格式与行为](Docs/Design/saved-request-logs.md)。
