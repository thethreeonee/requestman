# 保存与打开请求日志

日志以可直接阅读的 UTF-8 JSON 保存，默认文件名为 `Requestman yyyy-MM-dd HH-mm-ss.requestmanlog.json`。不依赖 Requestman 即可用文本编辑器、浏览器 JSON 查看器或脚本阅读。它与保存规则、环境和偏好的 `.requestman.json` 配置归档是不同的文件格式。

## 入口

- 请求日志的单条右键菜单提供“保存当前请求会话…”，保存右键所指的记录，菜单打开后的选中行变化、列表更新或清空不会更换目标。
- macOS“文件 → 保存当前日志…”（⌘S）保存当前搜索和筛选条件匹配的全部记录，保留列表顺序，不限于可见屏幕范围。重放导航临时显示但不符合筛选的记录不纳入保存。无匹配结果时禁用。
- “文件 → 打开日志文件…”（⌘O）通过原生文件面板读取 JSON，完整校验后在请求日志页显示。失败保留原页面和记录。

保存时固定记录集合，后台冻结流存储的已写入边界；活动连接不等待结束。写入使用同目录临时文件与原子替换，失败不覆盖已有文件。

## 文件内容

顶层包含 `format: "requestman.log"`、`version: 1`、ISO 8601 UTC `savedAt`、中文 `fieldGuide` 字段说明和 `records` 数组。每一项保存：

| 字段 | 含义 |
| --- | --- |
| `record` | URL、方法、状态码、时间、耗时、环境名称、命中规则名称与执行步骤、错误、原始和最终 Header / Body，以及重放来源 ID |
| `stream` | 最终 SSE 事件或 WebSocket 双向消息，包括时间、方向、事件类型、事件 ID 和载荷；SSE 同时保留原始流字节 |
| `receivedStream` | 与最终流不同时，单独保存上游原始 SSE 内容 |
| `sharedStream` | 为 true 表示原始和最终流共用 `stream`，避免重复保存 |

`record.requestHeaders / requestBody` 是客户端原始请求，`sentHeaders / sentBody` 是代理发往上游的请求；`receivedHeaders / receivedBody` 是上游原始响应，`responseHeaders / responseBody` 是最终返回客户端的响应。Header 使用名称和值的数组，保留重复项、顺序和实际值。

协议版本与请求/响应 trailers 作为可选字段保存在 record 中，旧文件没有这些字段时继续兼容。

Body 保留采集状态、观察到的字节数、Content-Type 和 Content-Encoding。`payload.text` 保存可阅读的 UTF-8 原文；其他字节使用 `payload.base64`，两者只保存一种。JSON Body 仍保留原始文本，避免重新解析导致字段顺序或数字精度变化。完整 gzip / deflate 正文可解码为 UTF-8 时另附 `decodedText`，供外部阅读；打开文件以原始 `payload` 恢复，不以阅读副本替换原始字节。SSE/WS 消息的 `payload` 使用同样表示。

保存的是已采集的内容：未完成、未采集、不可用与完整 Body 保持区别，不将部分数据伪装为完整请求。SSE 保留尚未形成完整事件的原始尾部，不受界面当前页限制；WS 保留已经记录的消息。文件不包含可执行规则、工作区环境变量配置、证书或浏览器配置。

## 文件浏览与实时记录

打开文件后，顶部显示文件名和“返回实时日志”。实时捕获仍使用原内存历史继续收集，文件记录独立显示，不受实时历史 500 条淘汰规则影响。文件仍可搜索、筛选、查看详情、复制、另存和从完整请求手动重放；手动重放时返回实时日志，并应用当前规则。返回实时日志恢复之前的搜索、筛选和仍存在的选中记录。

打开文件不恢复连接，不发送请求，不修改捕获状态或规则配置。保存时未结束的连接显示“保存时：接收中 / 连接中”；未完成的重放显示“保存时重放尚未完成”，不提供取消实时连接的操作。文件中的规则名称保持保存内容，不跟随当前工作区中同 ID 的规则改名，也不跳转到该规则。文件浏览期间禁用暂停记录和清空，避免误操作后台实时历史。

不支持的格式、未知版本、损坏 JSON、重复记录 ID 或无效载荷会报错，不发布部分加载结果。SSE/WS 打开后恢复到独立的会话临时存储，供已有分页详情使用；关闭文件后随引用释放清理。

## 验证

`RequestLogArchiveTests` 覆盖原始/最终 HTTP 字节与重复 Header、可阅读 JSON、压缩正文阅读副本、执行轨迹、SSE 多页与不完整尾部、WS 双向二进制消息、活动状态、未知版本、损坏文件、超过 500 条日志和失败保存。`check-request-replay.py` 检查实际历史模型的文件/实时隔离、筛选导出和返回实时日志；`check-workspace-sidebar.py` 与 `check-request-filters.py` 在隐藏组件窗口检查菜单、快捷键和冻结右键目标。另运行宿主 Swift 6 类型检查。这些不是完整 App 文件面板或真实鼠标验收。
