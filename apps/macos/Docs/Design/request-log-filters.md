# 请求日志筛选与命中规则

2026-09-25，采用用户选定的[方案 2](request-log-filters-v2.png)。图片是静态设计参考，数据均为示例；实现保持系统控件默认样式，沿用当前窗口不设底部状态栏的约定。

## 筛选布局

暂停/继续与清空统一使用 32×32 pt 原生 `NSButton`；macOS 26 使用 `.glass` 和 `.circle`，旧系统使用 `.circular`。搜索使用标题栏原生 `NSSearchToolbarItem`，紧邻启动/停止捕获按钮左侧，仅在“请求日志”页显示；样式和空间不足时的收缩由系统工具栏管理，不添加玻璃包装。切换页签保留搜索条件，输入与清除更新同一 `CaptureRecordFilter.search`，Popover 重置同步清空标题栏搜索。

列表顶部单行依次为暂停记录、清空、资源类型、筛选按钮，不再重复显示搜索框。默认显示全部、JSON、文档、CSS、JS、图片，更多菜单提供字体、媒体、其他。主内容宽度不足时全部资源类型收进原生下拉菜单，不新增横向滚动。搜索匹配原始 URL、请求修改名称及已执行规则类型/名称。

筛选按钮打开系统 Popover，集中放置项目、环境、结果、方法、请求 Header 条件、反向匹配和重置。选择立即生效，关闭再打开保留条件。按钮数字表示面板中有效条件的数量，搜索和资源类型由各自控件显示。清空日志不重置条件；重置清除全部筛选（包含搜索和类型）。

资源类型优先读取最终响应 Content-Type，仅在缺少 MIME 时按最终 URL 扩展名分类。代理不能可靠识别浏览器 Fetch/XHR 发起方式，故用 JSON 等内容类型分类，不把 JSON 宣称为全部 Fetch/XHR。加密隧道归入其他。

## 请求 Header

- 默认原始请求，可选择修改后请求；后者使用代理准备的最终出站 Header 快照。Mock、重定向本地响应及准备出站前失败的请求没有此快照，不伪造空 Header。
- 每行包含名称、匹配方式和值，名称使用可输入/自动补全的原生 NSComboBox。名称框按原生固有高度布局，条件滚动区四周保留 8 pt 焦点光环留白；删除使用原生圆形减号按钮和至少 28 pt 的正方形点击区域，与输入框垂直居中。候选取当前记录和常见名称，按大小写不敏感去重；匹配名称忽略首尾空白及大小写，值保留大小写。
- 匹配方式为包含、等于、存在、不存在。存在/不存在不使用值；等于允许空值；未填名称或未填包含值的草稿不参与过滤。
- 支持最多 16 条条件，可选择满足全部或任一条件。同名重复 Header 中任一完整值命中即可。
- 项目、环境、结果、方法、资源、搜索和 Header 条件组取交集。反向匹配对此完整条件取反；只有反向开关、没有有效条件时仍显示所有记录。
- Header 不再截断或脱敏，Authorization 等字段可以按实际值筛选。外部标记不完整或未采集的 Header 采用不可判断语义，不能断言未记录字段不存在；无法判断的值不会仅因反向匹配而被纳入。与其他已确定条件组合时采用三值逻辑。

## 命中的规则

列顺序固定为：时间、状态码、请求、命中的规则、项目、环境、耗时。项目列只展示项目名称，耗时保持最后一列且右对齐。所有列支持拖动原生表头分隔线调整宽度，拖动过程中相邻列实时收缩或扩展，表头和行内容同步更新，全程保持无横向滚动。松手后按列标识保存，下次打开页面或 App 自动恢复；新请求、筛选及清空不重置列宽。窗口缩放或 Inspector 开关按保存比例适配可用空间，保留最小宽度，不覆盖已保存偏好；回到原宽度时恢复原布局。缺失或无效的偏好使用默认分配。

规则列展示成功执行步骤的“类型 · 请求修改名称”。类型来自真实 ModificationKind 并区分请求/响应方向，名称取请求开始时匹配的工作流快照，而不是 Header 字段名或当前已编辑的工作流。仍遵循首个匹配工作流执行的原有行为，不新增多工作流叠加。

每个方向最多 64 步，记录最多 128 条类型/名称快照；禁用步骤、Mock 后跳过步骤及执行失败的步骤不标为成功执行。后续步骤失败时保留此前已执行的条目。未执行任何规则时显示“—”；两条以内分行显示，更多以原生 +N 按钮打开完整列表；长内容提供全文提示。

## 列表视觉

按方案 2 使用 56 pt 行高、13 pt 主文字与系统交替行背景。普通请求为垂直居中的“方法标签＋URL”单行，不重复显示“已转发/已修改”；失败请求才增加第二行说明，并与 URL 左对齐。规则类型用次级文字颜色，名称用主文字颜色；多条规则分行展示。耗时小于 1 秒显示 ms，否则显示一位小数的 s。

状态码按实际数值分类：1xx 蓝色、2xx 绿色、3xx 橙色、4xx/5xx 红色；缺失或非标准范围显示次级颜色。响应为 200 但后续传输失败时，200 保持绿色，错误说明使用红色，避免改写状态码本身的语义。

方法标签按用户要求提供同色浅背景与 1 pt 细边框，常用方法统一 72 pt 宽度以对齐 URL：GET 等使用蓝色、POST 橙色、PUT/PATCH 紫色、DELETE 红色、HEAD/OPTIONS 次级灰色。标签不承载按钮行为，保留原生文本；色值使用系统动态颜色。表格选中时使用系统高对比前景色，取消选中后恢复语义色；方法标签同步切换选中状态，并在浅色/深色切换时重新绘制。
