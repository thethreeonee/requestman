# 请求日志筛选与命中规则

2026-09-27：日志筛选改为表格上方展开的原生 AppKit 条件表单。[旧方案图片](request-log-filters-v2.png) 仅保留作历史参考。

## 筛选布局

日志顶部保留暂停、清空、十一项资源类型和筛选按钮；类型控件的固有尺寸、窄窗口双行布局、原生样式及最小宽度不变。标题栏继续使用 `NSSearchToolbarItem` 搜索当前显示列的内容，包含已启用的额外列；隐藏列不参与搜索。

筛选按钮与 `⌘⌥F` 在表格上方展开／收起配置表单，不再打开 Popover。操作栏与表单使用独立的兄弟容器，操作栏固定在顶部；表单保持完整布局，通过裁切区在 0.2 秒内平滑展开／收起，并同步让出表格空间。高度逐帧更新时关闭隐式动画，不对顶部附件的祖先视图做整体布局动画，避免按钮与标题栏跳动。连续切换从当前可见高度反向过渡，日志刷新不打断动画；系统开启减少动态效果时立即切换。macOS 26+ 表单跟随原筛选栏挂载在主分栏顶部附件中，旧系统使用内联布局。附件只在日志页挂载，离开日志页时移除，返回时保留展开状态和条件。

表单按条件、条件组和底部操作行的实际内容高度布局，不设置最小高度；增加条件或条件组时增高，删除或重置时缩回。上限为 320 pt 且不超过窗口内容高度的 45%；超过可见高度时内部使用原生滚动视图。底部固定反向匹配、多值输入提示和重置按钮。收起、切换页面、清空记录均保留条件；重置清除搜索、资源类型和整个条件树，表单保持展开。搜索、资源类型或表单条件生效时，筛选按钮立即显示蓝底白色圆形 SF Symbol，并提示有效条件数量；输入和清除最后一个有效值时同步更新，无需回车或结束编辑。按钮保留原生玻璃外观，蓝色仅用于中央图标，四周留出玻璃边缘；仅展开表单或存在空草稿不着色。

## 条件与条件组

根组和每个子组均可选择“全部满足（和）”或“任一满足（或）”。同一个字段可以重复添加，子组可以和普通条件并列；界面支持两层子组，以保证窄窗口可用。子组使用原生 `NSBox` 和缩进，提供添加条件、添加条件组和整组删除。空条件与空组作为草稿保留，不参与筛选，尤其不会使“或”组匹配全部记录。

可选字段为 URL、域名、请求方法、状态码、命中规则组、命中规则、环境、结果、活动连接、请求 Header。搜索和资源分类与条件树取交集；反向匹配对完整结果取反。仅有反向开关、没有有效条件时显示全部记录。筛选默认只在当前会话生效。底部“重置”左侧提供原生“保存筛选项”复选框，勾选后立即保存当前搜索词、资源分类、完整条件树及反向状态，后续编辑自动更新，下次启动 App 自动应用。取消勾选清除已保存条件，但保留当前筛选；重置清空条件并在开启保存时同步保存空条件，不取消勾选。保存使用本机应用偏好，随全量偏好归档导出，不写入请求日志文件。打开文件时自动清空筛选、返回实时日志时自动恢复筛选均不覆盖保存快照；在任一视图中手动修改筛选仍会保存。

- URL 按原始 URL 包含或等于匹配，忽略大小写。
- 域名按原始 URL 的 Host 精确匹配，忽略大小写，不含端口或路径、不自动包含子域名。
- 请求方法忽略大小写；状态码匹配最终响应状态码。
- URL、域名、方法、状态码支持空格、英文／中文逗号分隔。同一行的正向值满足任一即可，所有以 `-` 开头的值都作为排除项；排除优先于正向命中。只有排除项时表示“除这些值之外”。单独的 `-` 作为未完成草稿忽略。
- 例如域名 `api.example.com static.example.com -ads.example.com` 表示前两个域名之一，且排除 ads；URL `/api /orders -tracking` 表示包含 `/api` 或 `/orders`，且不能包含 `tracking`。
- 环境、命中规则组、命中规则、结果按完整名称匹配，保留空格与逗号；多个名称通过重复条件和“或”组表达。条件表单中的规则名称使用捕获快照；标题栏搜索按当前显示名称匹配。
- 活动连接可选择“是”或“否”，与其他条件自由组合。

输入使用原生 `NSComboBox`，提供捕获值及常见方法／状态码候选，允许手动输入；刷新日志或清空候选不改变当前输入。条件值更新不重建编辑器，保持输入焦点。

## 请求 Header

Header 作为普通条件参与各层组合。选择“请求 Header”后，同一行按“Header 名称 → 操作 → Header 值 → 原始请求复选框”排列，末尾保留移除按钮；名称和值平分可用输入宽度。原始请求默认勾选，取消勾选后匹配修改后发出的请求 Header，复选框悬停提示说明两种来源。每条独立选择包含／等于／存在／不存在，存在／不存在时值输入禁用并提示“无需填写值”。值按完整原文匹配，保留空格、逗号、前导减号和大小写；同名重复 Header 中任一完整值命中即可。名称忽略大小写和首尾空白，支持常见名称及捕获名称候选。存在／不存在不使用值，等于允许空值；未填名称或未填包含值的草稿不参与筛选。

修改后 Header 使用代理准备的最终出站快照；本地 Mock、重定向及准备出站前失败时可能不可用。隧道、不可用快照及外部标记不完整的 Header 保持三值逻辑，不能断言未记录字段不存在；未知结果不因反向匹配而变为命中。缺失状态码或无法提取域名时，同样不能单靠排除项或反向匹配纳入记录。已确定的组内条件仍能按“和／或”消解未知结果。

## 资源分类

SSE／WS 与其他类型共用原生分段控件，统一互斥。普通 HTTP 优先按最终响应 Content-Type 分类，仅缺少 MIME 时按最终 URL 扩展名分类。代理不把 JSON 宣称为所有 Fetch/XHR；未解密隧道归入其他。消息详情与分页语义见[持续捕获](streaming-capture.md)。

## 命中的规则

列顺序固定为：时间、状态码、请求、命中的规则、环境、耗时。规则组名称合并到命中的规则列，耗时保持最后一列且右对齐。所有列支持拖动原生表头分隔线调整宽度，拖动过程中相邻列实时收缩或扩展，表头和行内容同步更新，全程保持无横向滚动。松手后按列标识保存，下次打开页面或 App 自动恢复；新请求、筛选及清空不重置列宽。窗口缩放或 Inspector 开关按保存比例适配可用空间，保留最小宽度，不覆盖已保存偏好；回到原宽度时恢复原布局。缺失或无效的偏好使用默认分配。旧七列偏好忽略已移除的规则组列，继续按其余列的宽度比例恢复。

规则列用两行展示命中的请求修改：上行为规则组名称，下行为请求修改名称。规则组保留请求开始时的名称快照；请求修改名称按捕获的工作流 ID 读取当前名称，改名后已有日志立即刷新，包括全文提示，暂停记录时同样生效。工作流已删除或记录没有工作流 ID 时回退到捕获名称。展示更新不改写捕获快照和已执行步骤，标题栏搜索同步按显示名称匹配。仍遵循首个匹配工作流执行的原有行为，不新增多工作流叠加。

每个方向最多 64 步，记录最多 128 条类型/名称快照；禁用步骤、Mock 后跳过步骤及执行失败的步骤不标为成功执行。后续步骤失败时保留此前已执行的条目。这些条目是执行步骤，不是多条命中的请求修改，不用于生成 +N 数量。列表按 matchedWorkflowID 展示唯一命中的请求修改，即使其没有成功执行的步骤也保留命中名称；没有命中时仅展示规则组名称。旧记录缺少工作流 ID 时回退到首条步骤的名称。长内容提供全文提示。

## 从日志创建 Mock

右击完整请求行选择“Mock 当前请求”，以原始方法与完整 URL 精确匹配，拆分预填原始请求的方法、URL（含查询参数）、Header 和 Body。Header 条目统一使用“修改”，不生成添加、覆盖或删除项；请求流程不添加“返回静态数据”，有完整上游原始响应时，响应流程依次预填原始状态码、Body、Header；原始响应缺失或不完整时留空，不以修改后的响应代替。菜单保存完整记录快照，日志插入或清空后仍使用点击时的数据；空白区域不显示菜单，未解密隧道或原始请求内容不完整时禁用并说明原因，响应失败或缺失不影响创建。

新规则优先插入首个启用且命中的规则组首位；没有匹配时使用当前规则所属启用规则组或首个启用规则组，无可用规则组才新建。随后跳转“请求修改”，选中新建项并显示请求流程，展开所在规则组、清除会隐藏新建项的搜索条件并滚动到该项。正文编码、传输 Header 与字面值语义见 [macOS README](../../README.md#从日志创建-mock)。

## 列表视觉

按方案 2 使用 56 pt 行高、13 pt 主文字与系统交替行背景。普通请求为垂直居中的“方法标签＋URL”单行，不重复显示“已转发/已修改”；失败请求才增加第二行说明，并与 URL 左对齐。规则组名称在上行使用次级文字颜色，名称在下行使用主文字颜色；每条请求只展示一次命中的请求修改，不显示步骤数量。耗时小于 1 秒显示 ms，否则显示一位小数的 s。

状态码按实际数值分类：1xx 蓝色、2xx 绿色、3xx 橙色、4xx/5xx 红色；缺失或非标准范围显示次级颜色。响应为 200 但后续传输失败时，200 保持绿色，错误说明使用红色，避免改写状态码本身的语义。

方法标签按用户要求提供同色浅背景与 1 pt 细边框，宽度随方法文字自适应，左右各保留 6 pt 内边距，不设统一宽度；方法标签始终保留完整文字所需宽度，不按请求列宽比例压缩。请求列最小宽度随当前记录中最长的方法标签计算，URL 使用剩余空间并按需省略。GET 等使用蓝色、POST 橙色、PUT/PATCH 紫色、DELETE 红色、HEAD/OPTIONS 次级灰色。标签不承载按钮行为，保留原生文本；色值使用系统动态颜色。表格选中时使用系统高对比前景色，取消选中后恢复语义色；方法标签同步切换选中状态，并在浅色/深色切换时重新绘制。

## 验证

- `RequestLogFilterPreferencesTests` 覆盖完整条件往返、空条件、关闭保存及损坏偏好回退；`check-request-filter-persistence.py` 仅运行历史模型，检查开启、持续保存、重启恢复、重置和文件切换，不创建界面。
- Core 测试覆盖各层和／或、多值正向与排除、空草稿、缺失字段和 Header 三值逻辑，以及原有搜索、分类、反向和 Header 快照语义。
- `check-request-filters.py` 在隐藏组件窗口检查展开／收起占位、条件保留、新增条件和组、组内逻辑切换、字段切换、文本编辑焦点、多值输入、清空日志保留输入、最小宽度／820／1440 pt 横向边界、Header 来源和名称、删除组及重置；保留原表格、列宽、资源分类与菜单回归。
- `check-workspace-sidebar.py` 检查搜索、页签与顶部附件；宿主 Swift 6 类型检查独立执行。

这些检查不构建或运行完整 App，不等同于真实 App 下滑动画、鼠标操作、深色外观及 VoiceOver 验收。
