# 请求详情 Inspector

2026-09-25；基于用户选定的[第二版设计稿](request-inspector-v2.png)。图中是同一侧栏的两种状态，不是同时出现的两块内容。

## 信息与控件

- 工作区由一个原生 `NSSplitViewController` 承载项目侧栏、主内容和请求详情，三个内容宿主持久保留。两侧采用系统 sidebar / inspector 角色与全高布局，窗口启用 `fullSizeContentView`；右栏默认 520 pt，可在 400–760 pt 调整。内容区直接从请求摘要开始，使用贯穿右栏的系统 Inspector 背景。
- 窗口只有一条原生 `NSToolbar`，唯一详情开关使用原生 `NSToolbarItem`，显式连接分栏控制器的 `toggleInspector` 动作；由 AppKit 提供 SF Symbol 和系统默认按钮外观，不添加自定义视图包装。请求日志页展开、收起后都保留该按钮，未选中有效记录时禁用，请求修改页不显示。“请求详情”标题仅在展开时出现在跟随分栏边界的工具栏分隔线之后，左对齐，使用 `NSFont` 的 `.title2` 对应字号与 semibold 字重，无边框或额外玻璃背景。详情不再声明 SwiftUI 工具栏，列表也不另放展开按钮。
- 整个窗口与详情均不设底部状态栏。详情上方保留方向、数量、“仅显示变更”和内容提示，数据区域延伸至底部操作区上方。
- 顶部直接以 URL 为标题，不另显示域名和第二行 URL；单行保留首尾、中间省略，系统悬停提示显示已记录的完整地址。点击原生 URL 按钮打开系统 Popover，全文可选择、折行，超长时可滚动，并提供“复制完整 URL”按钮。记录已截断时明确说明地址不完整并禁用完整复制；侧栏收起时关闭 Popover。摘要保留原始方法、最终状态码、总耗时和响应大小；URL 下方另有“查询参数”入口，独立查看原始/最终参数，不混入请求体。
- “修改前 / 修改后 / 修改对比”显示模式位于展开右栏的顶部标题工具栏，紧邻更多按钮左侧。使用原生 `NSSegmentedControl` 的 `.automatic` 样式和 `.large` 尺寸，macOS 26+ 采用控件自身的 `.capsule` 形状，macOS 27+ 使用 `.tabs` 语义，不添加玻璃包装。整个 Inspector 共用一份显示模式，默认修改后，在四个内容 Tab、收起重开和选择不同记录时保持。
- 更多菜单移到展开侧栏的原生工具栏、收起按钮左侧，折叠时隐藏。使用 `NSMenuToolbarItem` 和 `isBordered = true` 保留系统默认按钮外观，不额外包装玻璃。菜单按顺序提供“复制完整 URL / 复制原始请求为 cURL / 复制修改后请求为 cURL”，各项继续依据记录完整性决定是否可用。
- cURL 分别使用修改前、修改后的方法、URL、Header 与 Body，保留实体字节，传输分帧和长度由 curl 重建。URL、Header 或正文未完整采集时禁用对应导出项并提供原因；Header 使用采集原值，不做脱敏。URL 记录已截断时不能称为“完整 URL”，对应复制项禁用。
- 命中规则才显示入口，弹出框保留项目、环境和步骤。没有规则时不预留空白模块。
- 一排“请求头 / 请求体 / 响应头 / 响应体”直接使用原生 `NSSegmentedControl`，macOS 26+ 使用控件自身的 `borderShape = .capsule`，macOS 27+ 同时使用 `.tabs` 语义；保留 `.automatic` 分段样式，通过 `.fillEqually` 均分可用宽度；macOS 26+ 采用原生 `.extraLarge` 尺寸，旧系统为 `.large`，不使用紧凑居中布局。整行固定为控件固有高度，Tab 和复制按钮均设置垂直抗拉伸/抗压缩，复制桥接显式返回固有尺寸，避免其分走内容区域高度造成大块空白。同一行右侧放置复制当前 Tab、当前显示模式内容的原生按钮；加载中或无可复制内容时禁用。不额外添加玻璃包装。
- 底部只保留搜索和 JSON 原始数据切换，横向 12 pt、纵向 10 pt 留白与左栏一致，不再放置版本按钮。底部格式切换与 Tab 右侧复制按钮在 macOS 26+ 使用控件原生 `.glass` 样式，不叠加玻璃容器。`NSSearchField` 使用大号系统搜索外观，不额外包装玻璃。请求体、响应体的 JSON 树通过“原始数据”按钮切换为源码，源码状态下按钮改为“树形视图”；格式切换不改变当前显示模式。
- Header / JSON 共用原生 `NSOutlineView`，原始数据用只读 `NSTextView`，保留文本原有的缩进、换行和字段顺序，不重新格式化。非 JSON 直接显示文本或十六进制，不展示无效的切换按钮。内容容器、字段树及原始数据视图不铺设独立白底；背景、文本、选中效果随系统外观变化，无自绘导航或代码编辑器。
- Header / JSON 字段表悬停保持箭头光标；源码和搜索框保留系统文本光标。保活的原生视图同时同步 `isHidden`，未选中的 Tab、树形/源码切换、加载和空内容状态不会留下隐藏文本视图的光标区域；视图实例仍保留滚动状态。
- URL Popover 的“复制完整 URL”按钮在 macOS 15+ 显式使用系统默认箭头，避免悬停时沿用父窗口边缘的缩放光标；macOS 14 保留系统默认行为。光标设置仅作用于按钮，URL 文本继续使用原生选择交互。
- 有子节点的 Object / Array 字段名称使用粗体，展开和收起时均保留；叶子字段与空容器使用常规字重，主表和 JSON 预览 Popover 保持一致。可双击展开或收起当前层级，使用 `NSOutlineView` 的原生双击动作；单击仍只选择，左侧展开箭头照常使用，复制按钮区域不触发展开。
- 用户最新修订优先于设计稿：字段不显示“已修改”“新增”等标签，只以淡背景区分。原始/最终对照保留必要的版本文字。父节点仅因子项变化时不染满祖先行。
- 行悬停时原生复制按钮以 0.15 秒淡入淡出，减少动态效果时直接切换。快速反向 hover 从当前透明度继续，行复用与窗口失焦立即清除旧状态。复制只包含当前字段值；对象/数组复制完整合法 JSON 子树。筛选不改变复制内容；右键菜单和 ⌘C 可完成同样操作。
- 字符串字段首次悬停时后台尝试解析其实际内容；有效 JSON 额外显示原生“查看 JSON”按钮，与复制按钮一起淡入淡出。点击后在系统 Popover 内复用同一字段树，可展开、复制和继续检查嵌套 JSON 字符串；原行保持 String 类型与原复制内容。解析不设置应用层大小、深度或节点上限，不尝试预览未完整采集的 Header；普通文本不显示入口。
- 每个内容 Tab 独立保留搜索、树形/原始数据格式、展开和滚动状态，显示模式由整个 Inspector 统一持有。搜索或“仅显示变更”自动展开保留路径；普通浏览恢复先前状态。手动收起右栏保留选择和这些状态，原生 `isCollapsed` 通过 KVO 同步内容可见性，不重建宿主。选择另一条记录释放旧解析结果，保留当前数据 Tab 和显示模式。

## 数据契约

请求原始/最终分别是客户端提交和发往服务器的内容；响应原始/最终分别是服务器返回和代理发往客户端的内容。Mock 的服务器响应不可用，不等于空 Body。顶部状态码为最终值，当前响应版本的状态码在内容说明行中标出。

原始/最终流量旁路完整采集 Body，不设置单份尺寸或共享内存预算，不落盘。HTTP 事务不等待 UI 或完整 Body，收到数据块后继续转发。完整、断流、未采集、不可用明确区分；写失败不能被后续成功掩盖。

只对完整快照后台解码 gzip / deflate，不设置解压输出大小或编码层数上限。JSON 使用 Foundation 解析，不设置应用层大小、深度或节点数限制。无法解析时仍提供已留存文本/字节并解释原因。URL、Header 名称、数量和值完整保留，所有凭据直接展示、比较和复制；cURL 导出保留实际请求 Header 值。未完整采集的字段不用于推断具体值变化。

## 验证

自动检查：Swift package 核心及本机回环 HTTP/HTTPS 测试；`check-request-inspection.py` 的 Header、JSON、复制内容和解压边界检查，以及 sh/zsh 中通过本地 curl 替身验证导出参数、引号转义和正文原始字节（不发网络请求）；`check-native-sources.py --typecheck` 的 Swift 6 类型检查及工程源文件引用校验。`check-workspace-sidebar.py` 使用实际原生工作区壳和模型、内容替身，在不显示的 `NSWindow` 中检查分栏布局、唯一工具栏及状态同步；检查范围不等于真实 App 视觉验收。

人工验收重点：右栏从窗口顶部贯穿到底部、标题左对齐且仅在展开时出现、窗口与详情无底部状态栏；原生详情按钮在展开和收起后均保留，未选择时禁用，请求修改页不显示，未聚焦任何控件时仍能切换；显示模式位于更多按钮左侧，更多菜单位于收起按钮左侧，均随右栏折叠隐藏；长 URL 点击后可选择、滚动和复制，截断状态准确；400/520/760 pt 侧栏宽度与浅深外观；显示模式跨内容 Tab、收起重开和记录选择保持，各 Tab 搜索、展开及原始数据格式独立保留；悬停按钮可点击且不改变当前选择；复制根/对象/数组后可作为 JSON 解析；搜索命中深层节点后可见；清空日志时旧内容消失；大正文和错误响应的状态准确。
