# 请求详情 Inspector

2026-09-25；基于用户选定的[第二版设计稿](request-inspector-v2.png)。图中是同一侧栏的两种状态，不是同时出现的两块内容。

## 信息与控件

- 工作区由一个原生 `NSSplitViewController` 承载规则组侧栏、主内容和请求详情，三个内容宿主持久保留。两侧采用系统 sidebar / inspector 角色与全高布局，窗口启用 `fullSizeContentView`；右栏默认 520 pt，可在 400–760 pt 调整。内容区直接从请求摘要开始，使用贯穿右栏的系统 Inspector 背景。
- 窗口只有一条原生 `NSToolbar`，唯一详情开关使用原生 `NSToolbarItem`，显式连接分栏控制器的 `toggleInspector` 动作；由 AppKit 提供 SF Symbol 和系统默认按钮外观，不添加自定义视图包装。请求日志页展开、收起后都保留该按钮，未选中有效记录时禁用；请求修改页复用该按钮控制步骤详情。“请求详情”标题仅在展开时出现在跟随分栏边界的工具栏分隔线之后，左对齐，使用 `NSFont` 的 `.title2` 对应字号与 semibold 字重，无边框或额外玻璃背景。详情控制器不另建工具栏，列表也不另放展开按钮。
- 整个窗口与详情均不设底部状态栏。详情上方保留方向、数量、“仅显示变更”和内容提示，数据区域延伸至底部操作区上方。
- 顶部直接以 URL 为标题，不另显示域名和第二行 URL；单行保留首尾、中间省略，系统悬停提示显示已记录的完整地址。URL 使用系统默认文字颜色的原生标签，点击不打开弹窗；同一行最右侧提供原生圆形“复制完整 URL”图标按钮，macOS 26+ 使用控件自身的 `.glass` 样式；按钮尺寸固定为 32 × 32 pt，SF Symbol 使用 13 pt 常规字重，保留图标周围留白。记录已截断时禁用完整复制，并通过按钮提示说明地址不完整。摘要保留原始方法、最终状态码、总耗时和响应大小；方法复用列表的紧凑彩色标签，状态码复用列表的 13 pt 等宽数字和蓝/绿/橙/红着色。查询参数位于请求头后的独立 Tab，不混入请求体。
- 显示模式位于更多菜单的“显示选项”原生子菜单，提供“修改前 / 修改后 / 修改对比”，以勾选标记当前值。默认修改对比，五个内容 Tab、收起重开及切换记录共用并保留该值。
- 更多菜单使用 `NSMenuToolbarItem` 的系统外观，位于收起按钮左侧，折叠时隐藏。以分隔线分为“重放 / 重新发送请求…”、“复制”子菜单和“显示选项”三组。“复制”子菜单依次提供“复制 URL”、当前 Tab 内容、“复制原始请求 cURL”和“复制修改后请求 cURL”；内容项随所选 Tab 显示“复制请求头 / 复制查询参数 / 复制请求体 / 复制响应头 / 复制响应体”，SSE / WebSocket 则对应“复制事件流 / 复制消息”，并复制当前显示模式的内容。菜单打开时固定复制快照，加载中或无可复制内容时禁用内容项。日志右键菜单复用重放和复制子菜单（不包含详情 Tab 内容项），并单独保留 Mock。
- cURL 分别使用修改前、修改后的方法、URL、Header 与 Body，保留实体字节，传输分帧和长度由 curl 重建。URL、Header 或正文未完整采集时禁用对应导出项并提供原因；Header 使用采集原值，不做脱敏。URL 记录已截断时不能称为“完整 URL”，对应复制项禁用。
- 命中规则才显示 14 pt 的原生 `NSPathControl` 面包屑，顺序为“规则组 > 规则”，用系统分隔符展示层级，不显示分支图标；不绘制点击后的焦点框，可点击时悬停使用手指光标；名称来自捕获快照，完整路径通过悬停提示和辅助功能值提供。点击直接跳转到对应请求修改，按捕获的工作流 ID 定位，不显示规则 Popover，目标已删除时禁用。没有规则时不预留空白模块。
- 一排“请求头 / 查询参数 / 请求体 / 响应头 / 响应体”直接使用原生 `NSSegmentedControl`，macOS 26+ 使用控件自身的 `borderShape = .capsule`，macOS 27+ 同时使用 `.tabs` 语义；保留 `.automatic` 分段样式，通过 `.fillProportionally` 按标签自然宽度分配可用空间，保证查询参数四字标签和 400 pt 窄栏完整展示；macOS 26+ 采用原生 `.extraLarge` 尺寸，旧系统为 `.large`，不使用紧凑居中布局。整行固定为控件固有高度，Tab 设置垂直抗拉伸/抗压缩并填满左右各 16 pt 留白之间的宽度；当前内容复制收纳在更多菜单的“复制”子菜单中，URL 和字段右侧的快捷复制按钮保留。不额外添加玻璃包装。
- 底部只保留搜索和 JSON 原始数据切换，横向 12 pt、纵向 10 pt 留白与左栏一致，不再放置版本按钮。底部格式切换按钮在 macOS 26+ 使用控件原生 `.glass` 样式，不叠加玻璃容器。`NSSearchField` 使用大号系统搜索外观，不额外包装玻璃。请求体、响应体的 JSON 树通过“原始数据”按钮切换为源码，源码状态下按钮改为“树形视图”；格式切换不改变当前显示模式。
- Header / JSON 共用原生 `NSOutlineView`，原始数据用只读 `NSTextView`，保留文本原有的缩进、换行和字段顺序，不重新格式化。非 JSON 直接显示文本或十六进制，不展示无效的切换按钮。内容容器、字段树及原始数据视图不铺设独立白底；背景、文本、选中效果随系统外观变化，无自绘导航或代码编辑器。
- 响应体的 `image/*` 内容完整采集并成功解码后，默认使用原生 `NSImageView` 居中、等比例缩小预览，不放大小图。右上角 Content-Type / 大小信息行下方提供“显示原始数据”原生复选框，勾选后切回已有文本或十六进制视图；图片预览时禁用文本搜索。修改前 / 修改后预览对应版本；修改对比采用左右等宽两列，左侧“修改前”、右侧“修改后”，分别预览对应图片，即使图片相同也保留两列。任一侧为图片即可展示对比；另一侧无响应、无 Body、非图片、数据不完整或无法解码时，在对应列显示原因，保留可用侧的图片。损坏、不支持或不完整的图片保留数据与原因提示，切换 Tab 保留当前选择。
- Header / JSON 字段表悬停保持箭头光标；源码和搜索框保留系统文本光标。保活的原生视图同时同步 `isHidden`，未选中的 Tab、树形/源码切换、加载和空内容状态不会留下隐藏文本视图的光标区域；视图实例仍保留滚动状态。
- 有子节点的 Object / Array 字段名称使用粗体，展开和收起时均保留；叶子字段与空容器使用常规字重，主表和 JSON 预览 Popover 保持一致。可双击展开或收起当前层级，使用 `NSOutlineView` 的原生双击动作；单击仍只选择，左侧展开箭头照常使用，复制按钮区域不触发展开。
- 用户最新修订优先于设计稿：字段不显示“已修改”“新增”等标签，只以淡背景区分。原始/最终对照保留必要的版本文字。父节点仅因子项变化时不染满祖先行。
- 行悬停时原生复制按钮以 0.15 秒淡入淡出，减少动态效果时直接切换。快速反向 hover 从当前透明度继续，行复用与窗口失焦立即清除旧状态。复制只包含当前字段值；对象/数组复制完整合法 JSON 子树。筛选不改变复制内容；右键菜单和 ⌘C 可完成同样操作。
- 字符串字段首次悬停时后台尝试解析其实际内容；有效 JSON 额外显示原生“查看 JSON”按钮，与复制按钮一起淡入淡出。点击后在系统 Popover 内复用同一字段树，可展开、复制和继续检查嵌套 JSON 字符串；原行保持 String 类型与原复制内容。解析不设置应用层大小、深度或节点上限，不尝试预览未完整采集的 Header；普通文本不显示入口。
- 每个内容 Tab 独立保留搜索、树形/原始数据格式、展开和滚动状态，显示模式由整个 Inspector 统一持有。搜索或“仅显示变更”自动展开保留路径；普通浏览恢复先前状态。手动收起右栏保留选择和这些状态，原生 `isCollapsed` 通过 KVO 同步内容可见性，不重建宿主。选择另一条记录释放旧解析结果，保留当前数据 Tab 和显示模式。

## 数据契约

请求原始/最终分别是客户端提交和发往服务器的内容；响应原始/最终分别是服务器返回和代理发往客户端的内容。Mock 的服务器响应不可用，不等于空 Body。顶部状态码为最终值，当前响应版本的状态码在内容说明行中标出。

原始/最终流量旁路完整采集 Body，不设置单份尺寸或共享内存预算，不落盘。HTTP 事务不等待 UI 或完整 Body，收到数据块后继续转发。完整、断流、未采集、不可用明确区分；写失败不能被后续成功掩盖。

只对完整快照后台解码 gzip / deflate，不设置解压输出大小或编码层数上限。JSON 使用 Foundation 解析，不设置应用层大小、深度或节点数限制。无法解析时仍提供已留存文本/字节并解释原因。URL、Header 名称、数量和值完整保留，所有凭据直接展示、比较和复制；cURL 导出保留实际请求 Header 值。未完整采集的字段不用于推断具体值变化。

## 验证

自动检查：Swift package 核心及本机回环 HTTP/HTTPS 测试；`check-request-inspection.py` 的 Header、JSON、复制内容和解压边界检查，以及 sh/zsh 中通过本地 curl 替身验证导出参数、引号转义和正文原始字节（不发网络请求）；`check-native-sources.py --typecheck` 的 Swift 6 类型检查及工程源文件引用校验。`check-workspace-sidebar.py` 使用实际原生工作区壳和模型、内容替身，在不显示的 `NSWindow` 中检查分栏布局、唯一工具栏及状态同步；检查范围不等于真实 App 视觉验收。

图片预览检查：`check-request-inspection.py` 覆盖图片 MIME、gzip 解码、版本选择和不完整内容；`check-inspector-performance.py --images-only` 使用真实详情组件的隐藏窗口检查 GIF / PNG 预览、400/520/760 pt 下复选框位置与左右等宽布局、版本对应、原始数据切换、复制、Tab 状态保持和不可用图片提示。

视觉验收状态：待运行验证。按照项目约束，本轮不通过 Xcode 或 xcodebuild 构建、部署、运行 App；静态检查不能代替与设计稿同状态的截图比较。

人工验收重点：右栏从窗口顶部贯穿到底部、标题左对齐且仅在展开时出现、窗口与详情无底部状态栏；原生详情按钮在展开和收起后均保留，未选择时禁用，请求修改页对应步骤详情，未聚焦任何控件时仍能切换；显示模式位于更多按钮左侧，更多菜单位于收起按钮左侧，均随右栏折叠隐藏；长 URL 中间省略、悬停显示全文、点击无弹窗，右侧按钮可复制完整地址，截断状态准确；400/520/760 pt 侧栏宽度与浅深外观；显示模式跨内容 Tab、收起重开和记录选择保持，各 Tab 搜索、展开及原始数据格式独立保留；悬停按钮可点击且不改变当前选择；复制根/对象/数组后可作为 JSON 解析；搜索命中深层节点后可见；清空日志时旧内容消失；大正文和错误响应的状态准确。

## 重放交互

重放操作使用打开菜单时的原始请求快照，并应用发送时的当前规则。请求不完整时禁用两个发送入口并给出原因；捕获停止或切换中仅禁用直接重放，“重新发送请求…”仍可打开和编辑。实际发送时重新检查捕获状态，未启动时在窗口内提示并保留编辑内容。原记录保持不变，结果以独立重放 ID 写入新日志并关联来源；手动重放不受日志暂停影响。发送后选中新记录并滚动定位，即使当前筛选不匹配也临时显示；再次修改筛选恢复正常筛选。

“重新发送请求…”依据 [确认的设计稿](request-replay-dialog-v1.png) 打开 800 × 780 pt 原生 sheet：标题和说明下方为并排的方法与 URL；方法使用仅供选择的原生 `NSPopUpButton`，原请求使用扩展方法时将其保留为选项。请求头使用名称/值两列表格，提供数量、增删和自动生成字段提示，保留重复字段顺序及未编辑值的空白。请求体复用 `RequestmanEditor.CodeEditorView` 的行号与 JSON 语法着色，不格式化或解析模板；正文为 UTF-8 或 Base64，压缩内容保留其编码 Header。底部固定规则提示、状态和取消/发送按钮；两个按钮使用系统 `large` 尺寸，macOS 26+ 使用原生玻璃胶囊样式，发送按钮使用系统强调色。实时显示 URL、Header 和 Base64 校验错误；提交期间锁定编辑，取消仍可用。按 Escape 取消，按默认操作发送。提交失败保留编辑内容，提交成功后关闭 sheet 并在日志持续显示进度，不将提交成功当成响应完成。日志顶部保留最近重放状态和“查看重放结果”；活动请求提供“取消此次重放”。列表请求列与详情显示“重放进行中 / 重放已完成 · HTTP 状态码 / 重放失败 / 重放已取消”。HTTP 4xx/5xx 是已收到的响应，传输或代理错误才标为重放失败。

右键和详情更多菜单为活动重放提供“取消此次重放”，仅关闭该次连接；SSE 也可单独取消。重放记录的“查看原请求”回到来源记录；来源已清空或淘汰时禁用并说明原因。多次重放分别保留 ID 和状态，取消其中一个不影响其他请求或捕获。
