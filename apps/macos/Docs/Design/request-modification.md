# 请求修改配置（2026-09-26）

采用用户选定的方案 1，并合入 URL / Host 匹配与脚本 API 补充；[修订设计稿](request-modification-v3.png) 使用内置 Image Gen 生成。设计稿为布局参考，当前实现的控件外观由 macOS 系统绘制，执行契约以下文为准。

## 步骤悬停

请求、响应阶段的步骤行与规则树共用浅灰背景 hover 动画：移入 0.12 秒、移出 0.16 秒，使用 ease-in-ease-out 曲线。背景范围沿用步骤选中区域，文字、图标与行尺寸不变；选中行优先显示已有蓝色选中效果。快速移入移出从当前呈现透明度续接，窗口失焦、行移除或脱离窗口时清理；减少动态效果开启时直接切换终态。

两阶段的标题、方向说明与添加按钮固定在列表上方，步骤滚动区域延伸到标题后面。标题区域使用 `NSVisualEffectView` 的 `.headerView` 原生材质，让滚过的步骤在标题下方模糊；列表中不额外放置渐变模糊条。滚动容器以标题实际高度设置顶部 inset，初始首行位于标题下方，窄栏标题换行时保留当前滚动位置；标题下方的列表仍以 400 pt 为高度上限。添加按钮保留点击操作，标题区域的滚轮交给对应步骤列表，标题后的步骤不接收鼠标点击。窗口工具栏的滚动边缘效果仍由 AppKit 独立管理。

标题材质的顶部与两侧贴合阶段 1 pt 边框的内沿，顶部圆角按现有 8 pt 外框裁切；12 pt 的标题内容边距放在材质内部。材质下边缘止于分割线底部，分割线两端贴合阶段边框内沿。线下保留 10 pt 留白，计入列表顶部 inset，不覆盖模糊。步骤列表仍距外框左右各 4 pt，底部贴合 1 pt 边框内沿，不额外留白；分割线高度、首行位置和列表高度不变。

## 匹配测试

匹配区标题右侧提供“测试匹配”。Sheet 展示条件摘要，允许输入方法、HTTP/HTTPS URL 和多个示例 Header；Cookie 通过 Cookie Header 输入，Query 从 URL 读取。测试输入不持久化，不发送请求、不运行步骤。回车提交 URL 并测试，输入法组字时仍用于确认候选。正文随内容调整高度，达到屏幕可用高度后使用原生滚动，完成按钮固定在顶部。

后台测试直接复用条件组匹配器，逐项列出字段实际值、缺失状态和分组结果；任一组中的未命中分支不影响已成立的组结果。无效配置、无效样例与正常未命中分开显示。编辑输入清空旧结果，过期结果不回填。规则启用状态与规则顺序不参与本地条件测试；真实捕获仍只执行首个启用且命中的流程。

## 窗口和编辑

请求编辑区域从请求名称开始，不在名称上方重复显示所属规则组名。顶部名称默认只读，不接受自动编辑焦点，单击不进入编辑；双击后开启编辑并选中名称，新建后的显式名称编辑入口同样开启编辑。编辑期间保留原生单击定位光标和文本选择行为，结束编辑后恢复只读。侧栏菜单和 Return 重命名入口继续可用。

左侧以规则组分组，请求修改仅显示名称。编辑页顶部依次为名称、启用状态（随开关显示“已启用”或“已关闭”）；主体使用原生滚动容器，保持 24 pt 外边距。macOS 26+ 的主体铺满主面板并延伸到窗口标题栏和底部“预览流程”区域背后，顶部沿用原生工具栏滚动边缘，底部使用 `NSSplitViewItemAccessoryViewController`（26.1+ 为 `.soft`），由 AppKit 提供滚动柔化与内容 inset，保证首尾内容可滚动至完整可见。预览按钮固定在附件栏内，没有选中规则时隐藏，切换规则时替换附件内容；旧系统保留固定底栏布局。匹配条件及请求、响应阶段分别使用带边框的 `NSBox`。阶段标题与“添加步骤”位于边框内顶部，常规宽度按钮靠右，窄栏放到标题下方。两阶段保持并排，列表顶端对齐。

匹配区采用 Finder 式可增删条件行，根组与子组都支持“全部 / 任一”。原生 disclosure 控件分别收起整个匹配区和子组，收起显示条件数量及摘要，不改变规则内容。每行支持停用并保留值；存在、不存在、为空、不为空隐藏值输入。字段、运算符使用原生 popup，宽度统一为 125 pt。宽区域按“字段 → 名称（如有）→ 运算符 → 值（如有）”单行排列，相邻控件间隔 8 pt；URL 等无名称字段不预留名称空位。换行宽度按当前可见控件计算，单行名称预留 150 pt，值至少预留 160 pt，因此无名称或无值的条件可在更窄区域保持单行。空间不足时，第一行保留启用、字段、名称及右侧移除按钮，第二行依次显示运算符和值，两行间隔 8 pt，保持条件阅读顺序。窄布局的名称与值输入分别使用所在行的剩余宽度，内容保持单行横向滚动。切换宽窄布局和编辑值时保留原有控件与 field editor。无效条件在所属组显示错误。

macOS 26 及以上的添加、测试、移除、预览与匹配下拉控件使用原生 `.glass`，系统负责 macOS 26/27 的绘制；不增加玻璃或材质包装。复选框、开关、输入和列表均保留对应 AppKit 系统控件。步骤列表使用 `NSTableView`，选中行显示浅蓝背景、蓝色描边与 8 pt 圆角，描边左侧位于外框与序号色块之间的中点，左右距外框均为 6 pt；序号使用蓝色（请求）或绿色（响应）的圆角徽标，选中与未选中时左侧均与阶段分割线对齐，SF Symbol、标题和摘要组成 64 pt 行，停用图标放大并固定在行最右侧。阶段标题为 16 pt，分别带向右和向左箭头；“添加步骤”使用不带下拉箭头的原生玻璃按钮打开 `NSMenu`。保留原生拖动排序、键盘选择、右键停用与删除。列表超过 400 pt 后滚动。

点击其他步骤时选中并打开对应的窗口级 Inspector；再次点击已选中的步骤时切换右侧栏展开状态：已展开则收起，已收起则重新展开。收起保留步骤选择；键盘切换选择继续打开对应详情。删除或切换到没有有效步骤的规则后关闭。步骤详情不提供上移、下移按钮，排序通过列表拖动。窗口工具栏原“步骤详情”位置显示当前步骤的图标和名称，下方显示不超过 25 字的类型说明，替代阶段与序号；主副标题间距为 4 pt，原生启用开关使用 `.small` 尺寸，位于收起按钮左侧；开关左侧以 11 pt 次要文字显示“已启用 / 已停用”，间隔 6 pt，随当前步骤状态同步。右侧分栏与左侧一样使用 `NSSplitViewItem(sidebarWithViewController:)`，顶部使用原生工具栏及全高内容布局，由 AppKit 管理默认滚动边缘，不安装顶部附件或显式覆盖边缘样式。正文直接显示配置表单，不再重复标题、开关和说明。

菜单中的 11 种修改类型使用语义对应的 SF Symbol，统一显示在添加步骤菜单、步骤卡片的类型名称前和详情标题前。Header 修改使用调节图标，Body 使用文档、目标地址使用链接、查询参数使用调节图标、URL 替换使用循环箭头、请求方法使用双向箭头、状态码使用数字、静态数据使用文档副本、重定向使用转向箭头、脚本使用代码符号、延迟使用时钟。类型名称继续保留，图标不重复加入辅助功能朗读。

macOS 27 默认可能隐藏菜单项图片，添加步骤菜单显式设置原生 `preferredImageVisibility = .visible`，确保类型图标显示；旧系统继续使用 `NSMenuItem.image`。

Header 步骤统一命名为“修改 Header”，添加菜单仅保留一个入口。条目下方不展示添加、修改、删除及旧配置的操作说明。每条 Header 独立选择“添加”、“修改”或“删除”，同一步内可混用并按顺序执行；删除时隐藏值，切回时保留已输入值。添加始终追加一条，保留已有同名项；修改按不区分大小写的名称匹配已有项，更新所有匹配项的值并保留原名称、数量和顺序，没有匹配时跳过；删除移除全部同名项，不存在时跳过。新步骤序列化标识仍为 `setHeader`，旧 `removeHeader` 步骤同样以统一编辑器打开并保留删除行为。名称采用可编辑的原生 `NSComboBox`，可以从候选列表选择，也可输入完整自定义名称。候选项来自浏览器扩展 `ModifyHeadersRuleDetail.tsx` 的 `COMMON_HEADERS`，macOS 所有 Header 下拉框按不区分大小写的字母顺序展示。`Content-Length`、`Host` 等候选仍保留以便两端列表一致，但选择后明确提示其由代理维护，执行时继续拒绝非法改写。参见 [Apple NSComboBox](https://developer.apple.com/documentation/appkit/nscombobox)。

## 请求方法修改

“修改请求方法”的字段标题为“请求方法”，使用原生 `NSPopUpButton` 从 [IANA 注册的 HTTP 方法](https://www.iana.org/assignments/http-methods/) 中选择，常用方法排在前面。候选列表暂不包含当前不支持改写的 CONNECT、TRACE，以及 HTTP/2 连接前言专用的 PRI；不提供通配符。旧配置中不在候选列表内的方法或模板仅保留显示与原值，不能重新选择，只有主动选择候选方法才替换；空值显示“请选择请求方法”。选择后沿用步骤自动保存。

## Body 编辑

带行号的 Body（模板与字面值）和 JavaScript 编辑器共用 8 pt 外层圆角裁切，行号栏与正文视口上下对齐，不使用会仅缩进正文视口的内部 bezel 边框。

多行输入框按正文实际高度处理滚轮：内容未超出视口时，将滚轮及触控板事件交给外层表单；超出时保留原生正文滚动。内容缩短后恢复外层滚动，滚动条自动隐藏。此行为适用于 Header 值、Body、脚本及预览中的多行输入。

“返回静态数据”和请求 / 响应的“替换 Body”在表单顶部使用原生“文本 / 本地文件”分段控件，默认文本；样式与工作区切换一致，采用 `.automatic`、`.large`，macOS 26+ 使用 `.capsule` 原生玻璃外观，macOS 27+ 设置 `.tabs` 语义。选择本地文件后，通过“映射本地文件…”打开系统文件选择面板；表单显示已选路径，每次执行重新读取原始字节，不解析模板、不改变换行或二进制内容。文本草稿与文件路径分别保存，切换不会清空。未选择、文件不存在或无法读取时，该步骤失败并沿用流程错误提示，不回退到文本。配置和归档保存路径，不打包文件；换机器后需要重新选择文件。文件读取在代理和预览的后台执行；仅文件替换仍流式消费原始 Body，含脚本或延迟时沿用完整 Body 流程。

“替换 Body”和 Mock 的原生文本编辑区填满窗口剩余高度，最低 360 pt；窗口较小时外层表单可滚动。模板与字面值两种模式均按输入框边界裁切行号栏，避免溢出正文区域。文本视图按内容增长，长内容在编辑区内纵向滚动。显示逻辑行号（自动折行不增加行号）、JSON 键名、字符串、数字、布尔值及符号着色，保留模板变量标记。颜色跟随系统明暗外观，仍可输入任意纯文本。

Body 与脚本使用独立 `RequestmanEditor` 组件，CodeEditTextView 负责编辑，HighlighterSwift 负责随系统明暗切换的语法高亮，行号复用 CodeEditSourceEditor 的 MIT GutterView。请求日志的请求体 / 响应体 JSON 树和原始数据继续使用 `JSONSyntax`：key 蓝色、字符串绿色、数字橙色、布尔值和 `null` 紫色，结构符号使用次要文字色。原始数据着色不修改内容；搜索匹配继续使用背景高亮，树形选中行保留系统选中文字色。模板变量标记仅用于编辑器，Header 名称保持默认文字色。

Body 与 Mock 共用的“格式化 JSON”按钮在 macOS 26+ 使用原生玻璃药丸样式。格式化接受标准 JSON，以及 key 为未加引号的标识符、对象或数组末项带逗号的写法，例如 `{name: "张三",}`。仅在点击时将 key 补为双引号、移除末尾逗号，并使用两空格缩进和换行；保留字段顺序、数字原文、字符串转义及模板变量，支持撤销。字符串内模板原样保留，未加引号且作为完整值的模板按占位值检查结构；这不代表模板展开后的 JSON 一定有效。解析不执行 JavaScript 表达式；不支持的内容或语法不完整时显示提示并保留输入。着色与行号只影响显示；普通 Body 按文本 / 模板整体替换，不自动修改 Content-Type。从请求日志生成的请求 Body 默认按字面值保存，关闭“解析模板变量”；可在步骤详情开启。无法表示为 UTF-8 文本的捕获正文使用 Base64 保存原始字节，详情显示“Body · Base64”，隐藏 JSON 格式化按钮。

## URL 修改步骤

“改写请求 URL”修改代理实际访问的地址，保留请求方法和 Body；“返回重定向”返回 3xx 状态码和目标地址，由客户端发起新请求。添加菜单、步骤标题和详情共用这两个名称，配置区显示对应说明；序列化标识仍为 `rewriteURL` 和 `redirect`，执行行为不变。

“改写请求 URL”通过原生 `NSSegmentedControl` 切换“完整 URL / 主机 / 路径”，使用系统自动样式和 large 尺寸；macOS 26+ 使用 `.capsule` 胶囊形状，由系统提供玻璃外观，不添加材质包装。`urlRewriteTarget` 缺省时按完整 URL 处理，旧配置继续使用原有行为；切换目标保留输入内容。三个目标均支持环境变量与动态模板，值按现有 `literalValues` 约定解析。

上方统一说明“修改代理实际访问的 URL，可改写完整地址、主机或路径，保留请求方法和 Body。”，切换目标时保持不变。三个目标的输入框下方均提示正则捕获组引用语法，主机和路径另显示各自的输入说明。说明在当前 Inspector 宽度内换行，水平压缩优先级低于分栏宽度保持约束；切换目标不扩大右侧栏或窗口。捕获组改写已通过定向 Core 测试、代理回环测试和宿主静态类型检查；未运行 UI 测试，输入提示的界面效果待人工验证。

- 完整 URL：填写完整 HTTP/HTTPS 地址，替换整个请求 URL。
- 主机：填写域名或 IP，可附加端口，例如 `api.example.com:8080` 或 `[::1]:8080`。省略端口时保留当前 URL 的端口，显式端口须为 1–65535；保留协议、路径及查询参数。拒绝协议前缀、用户信息、路径、查询参数、片段及空白。代理仍根据最终 URL 生成 Host Header 和选择上游连接。
- 路径：以 `/` 开头，替换整段路径，保留协议、主机、端口及查询参数。中文和空格自动进行 URL 编码，合法百分号编码原样保留；字面 `?` 和 `#` 分别使用 `%3F` 和 `%23`，不接受查询字符串、片段、控制字符及无效百分号编码。

改写值可直接使用 `$1`、`$2` 等引用匹配条件正则中的捕获组，无需 JavaScript。例如 URL 正则 `^https://api\.example\.com/v1/([^/]+)/([0-9]+)$` 配合目标 `https://staging.example.com/v2/$1/$2`，会把 `https://api.example.com/v1/users/42` 改写为 `https://staging.example.com/v2/users/42`。完整 URL、主机、路径均支持，也可与 `{{$env.name}}` 模板混用。

捕获组在原始请求匹配时固定，后续 URL 修改不会重新匹配。条件组按当前条件顺序、再按子组顺序选择第一个命中且含捕获组的正则；禁用条件和整体未命中的子组不提供捕获值。使用该正则在首个匹配字段值中的第一次匹配，编号保持该正则自身顺序，不拼接多个正则的捕获组。`$0` 表示该次完整匹配，支持多位编号（如 `$12`）；可选分组未参与匹配时替换为空字符串，编号不存在或没有可用捕获组时本步失败。`$$` 表示字面 `$`（如 `$$1` 输出 `$1`）。环境变量与捕获值仅插入一次，其中的 `$1` 或模板表达式不会再次展开；`literalValues` 为 true 的既有字面值步骤保持原文。

主机和路径目标基于前一步处理后的当前 URL 执行，未修改部分的查询编码、重复参数、空查询均保留；校验失败不提交本步修改。模板中的 `$request.*` 仍引用原始请求快照。HTTP 请求不包含浏览器 fragment，因此不提供片段修改目标。

请求阶段新增“修改查询参数”和“替换 URL 字符串”，与其他步骤按顺序作用于当前 URL，命中日志保留对应类型。两项均支持多个配置区块、环境变量与动态模板，响应阶段不提供。

- 修改查询参数：参数配置区域使用独立的原生表单区块，每条选择添加、修改或删除，按显示顺序执行；添加遇到同名跳过，修改仅更新已有的全部匹配参数，删除移除全部匹配参数、未匹配时跳过。添加和修改显示名称和值，删除仅显示名称，切回时保留已输入值。支持增删条目与空列表，空列表不操作；配置通过 `queryParameters` 保存。名称区分大小写，空值保留 `name=`，名称和值按 UTF-8 URL 编码，未修改参数的原始编码、顺序和重复项保持不变，`+` 视为加号。整组成功后才更新 URL；删除及无需执行的添加/修改不解析未使用的值。旧 name/value 配置保留原有“不存在时追加、同名覆盖合并为一项”行为，表单显示兼容说明，显式选择操作后采用新语义。标题、启用开关和步骤删除区域保持不变。
查询参数的“添加参数操作”和 URL 字符串替换的“添加替换配置”按钮均固定在 footer 左侧，与 Header 添加按钮共用原生胶囊玻璃样式和系统 `large` 尺寸，不随配置列表滚动。

查询参数的执行语义、名称大小写与 URL 编码说明统一放在标题下方，使用与修改 Header 相同的次要说明样式；条目内部和添加按钮下方不再重复显示说明。存在旧配置时兼容说明也合并在标题下方，选择新操作或匹配规则后同步移除。

参数名称使用原生单行输入框，长内容横向滚动，回车提交并结束编辑；参数值继续使用多行编辑器。

修改与删除的操作行提供参数名称匹配规则：等于、包含、通配符、正则，默认等于；添加时隐藏并忽略匹配规则，切回修改或删除时保留选择。规则保存在每条参数的 `matchRule`，旧条目缺省按等于读取。匹配 URL 解码后的参数名称，默认区分大小写；通配符整名称匹配（`*` 任意字符序列、`?` 单个字符），正则沿用现有匹配器的查找语义，可用锚点限制全名。修改只更新所有匹配参数的值，保留各自名称及名称原有编码；删除移除全部匹配参数。无效正则拒绝整组操作，不保留前面条目的部分修改。

- 替换 URL 字符串：每个配置使用独立原生表单区块，可添加、删除；查找字符串使用单行输入框，替换值保留动态模板编辑器。区分大小写说明置于步骤标题下方。每块按原文强制替换整个 URL 中的全部匹配，不使用正则，也不提供仅替换首项的选项；后续区块作用于前面替换后的 URL，同一区块不会再次匹配自己生成的内容。查找字符串不能为空，替换为空会删除匹配内容；未匹配时保持 URL 不变。通过 `urlReplacements` 保存，缺省时读取旧 `name/value` 单组配置，显式空列表不操作。每块替换后校验 URL，整组成功后才更新请求；失败不留下半组修改。

两项完成后校验最终 HTTP/HTTPS 地址；无效结果报错，不写入当前 URL，也不计入成功执行步骤。步骤卡片展示参数赋值或替换关系。Core 测试覆盖编码、重复项、执行顺序、模板、保存恢复与失败；回环代理测试检查上游实际收到的路径和日志中的最终 URL，不能代替浏览器验收。

## 响应延迟

响应阶段的“添加步骤”提供“添加延迟”，详情使用原生单行输入框，单位为 ms，默认 1000。时间为非负整数，0 立即继续；空值、负数、小数和超出整数范围的值显示错误，执行时拒绝。步骤卡片显示“等待 N ms”。延迟沿用步骤启停、排序、复制和配置保存，不提供请求阶段入口。

流程到达延迟步骤时异步等待，等待完成才记录该步成功并执行后续步骤；连续延迟依次累加。普通上游响应与 Mock 响应均生效，本地预览执行相同等待。含延迟的响应沿用后台完整 Body 流程，完成全部响应步骤后才向客户端发送响应头和正文；仅含延迟时不解码文本、不占用脚本执行名额，原始二进制和压缩内容保留。等待使用单调时钟，不阻塞网络线程或主线程。

HTTP 请求事务和流程预览不设总时限，超过 30 秒的延迟仍会等满后继续下一步。客户端断开、停止捕获或关闭预览时取消等待，不执行下一步，也不把未完成的延迟记录为成功。自动识别的 SSE 响应在响应头阶段执行延迟，响应脚本仅可处理此前 Body 替换生成的有限内容；其他响应的延迟或脚本沿用完整 Body 流程。

## 匹配

`RequestWorkflow.matchConditions` 是唯一匹配模型，包含可停用的条件、嵌套子组和全部 / 任一逻辑。工作区格式为 3，不提供旧匹配配置迁移；新建、复制、保存、归档及日志生成 Mock 均直接使用条件组。复制与导入为组和条件重新生成 ID。

| 字段 | 取值与运算符 |
| --- | --- |
| URL | 完整地址，区分大小写 |
| Host | 不含端口的主机名，忽略大小写；支持域名及子域名的标签边界匹配 |
| Path | 不含 Query，保留百分号编码；空路径为 `/` |
| 方法 | 等于、不等于、属于、不属于；集合以逗号分隔，忽略大小写 |
| 协议 / 端口 | HTTP/HTTPS 与有效端口；未显式填写端口时 HTTP=80、HTTPS=443 |
| Query | 参数名精确匹配，百分号解码，`+` 保持字面量；重复参数保留独立值 |
| Header | 名称忽略大小写，值区分大小写，重复项不拼接 |
| Cookie | 解析请求 Cookie 的分号条目；名称和值区分大小写，不解码值 |
| Content-Type | 提取分号之前的媒体类型并忽略大小写 |

文本字段支持等于、不等于、包含、不包含、开头、结尾、通配符、正则。通配符整串匹配，`*` 为任意长度、`?` 为单个字符；正则为 ICU 搜索，保留原匹配时间预算。具名字段另支持存在、不存在、为空、不为空。存在允许空值；缺失与空值分开。正向条件任一同名值满足即可，否定条件要求字段存在且所有值均不满足。

停用条件不参与计算；没有启用条件的组不匹配请求。启用但无效的条件使整个匹配配置无效，不因位于任一组而被忽略。条件在修改前对原始请求判断，首个启用且命中的规则执行，请求修改后不会重新选择规则。本轮不提供 JSON、Body、响应条件或来源 App 匹配。

## 脚本 API

两个阶段的“添加步骤”均包含“执行脚本”。代码为 JavaScript async 函数体，可直接使用 await、Promise 和 Promise.all，请求阶段必须返回 `request`，响应阶段返回 `response`（也可返回具有同样结构的新对象）。脚本不作模板展开，环境变量通过 `env.name` 读取。

执行失败说明统一显示在步骤标题下方，步骤备注使用白色输入背景。脚本代码编辑器提供 JavaScript 关键字、字符串、模板字符串、注释、数字和函数调用高亮，以及随滚动同步的逻辑行号；自动换行不重复编号，颜色不写入脚本文本或撤销记录。脚本编辑器仅保留“试运行”入口，点击后打开 900 × 620 pt 对话框，不立即执行。左侧编辑示例输入，右侧显示只读结果；底部“运行”使用当前输入执行脚本，错误也在同一区域展示。输入变化后取消在途运行并提示重新运行，关闭时取消执行，重新打开保留本次编辑器会话中的输入。编辑页不再显示独立的示例输入按钮、运行结果或分段切换。

所有步骤详情右下角的删除按钮使用原生玻璃按钮（macOS 26+，`borderShape = .capsule`）的系统 `large` 尺寸，删除图标用系统红色 Symbol 调色板，文字用系统红色前景色，避免玻璃按钮忽略 tint 后显示黑色。Header 添加按钮同样使用原生胶囊形状和系统 `large` 尺寸；两者均不自定义字体、背景或材质包装。步骤备注采用支持白底的原生文本框边框样式；流程预览中的“请求与响应输入”保持 600 × 540 pt，“预览流程”保持 680 × 500 pt。输入表单在固定窗口内滚动，滚动条遵循系统显示偏好；试运行左右编辑区等宽，与中间分隔线各留 24 pt，左侧滚动条位于这段间隔内，显示或隐藏都不改变字段边缘；长 URL 在单行输入框内滚动。左侧 Header 与 Body 多行输入使用 8 pt 圆角，聚焦时显示 AppKit 系统焦点环，失焦后消失；滚动视口为左侧和底部焦点环预留绘制空间，字段位置与列间距不变；聚焦 Header 或 Body 输入框时，外层表单滚动到完整显示输入框及焦点环的位置。右侧结果保持只读。

```ts
type Header = { name: string; value: string };
type Request = {
  method: string;
  url: string;
  headers: Header[];
  body: string | null;
};
type Response = {
  status: number;
  headers: Header[];
  body: string | null;
};
// 每次执行注入：
request: Request;
response: Response | null;
env: Record<string, string | number | boolean | unknown[] | Record<string, unknown>>;
```

请求阶段 `request` 是之前步骤处理后的请求，`response` 为 `null`。响应阶段 `request` 是只读的发出请求快照，`response` 是之前步骤处理后的响应。`env` 始终只读。Header 使用数组，保留大小写与重复项（例如多个 `Set-Cookie`）；比较名称时忽略大小写。

`body` 为完整 UTF-8 文本，JSON 也以字符串提供，使用 `JSON.parse` 和 `JSON.stringify` 处理。gzip / zlib-wrapped deflate 在后台解码；不支持的编码、损坏压缩或非 UTF-8 内容为 `null`。空正文是 `""`。返回 `null` 保留已有正文，返回空字符串清空正文；仅当文本实际改变时替换正文并清除原编码、摘要、范围与缓存校验 Header，代理重建 Content-Length / Transfer-Encoding。未修改的压缩和二进制正文原样转发。

```js
// 请求阶段
request.headers.push({ name: "X-API-Key", value: env.apiKey });
return request;

// 响应阶段
const data = JSON.parse(response.body);
data.debug = true;
response.body = JSON.stringify(data);
return response;
```

`method` 不支持 CONNECT / TRACE，`url` 必须为无用户信息及片段的完整 HTTP/HTTPS 地址，`status` 为 200–599 整数。Host、Content-Length、Transfer-Encoding、Connection、Upgrade、Trailer 可读取但不能由脚本改写。所有返回字段校验成功后才提交草稿，失败不会部分提交脚本结果。

“API 帮助”在编辑器内展示相同结构、格式和示例。“示例输入”可编辑请求 URL、方法、Header JSON 数组、请求文本，以及响应状态、Header、文本；“试运行”使用当前环境和真实脚本执行器，显示 JSON 结果或错误；“运行”默认离线，fetch 明确报错。“真实联调”需先启动捕获，只发送脚本辅助请求，主请求与响应仍使用样例。“预览流程”另校验测试 URL 是否命中，再按顺序执行两阶段。fetch API 见[异步脚本与辅助 HTTP](async-scripts.md)。

## 执行与验证边界

使用系统 [JavaScriptCore](https://developer.apple.com/documentation/javascriptcore/jscontext) 和一次一脚本的独立进程；App 同一可执行文件通过专用参数进入工作模式，在创建 NSApplication 之前返回，SwiftPM 测试使用独立 worker target。没有导出原生对象、文件、DOM、Node.js API 或定时器。worker 在固定线程等待 Promise，通过双向 RPC 将 fetch 交给宿主 HTTP 服务；结果序列化仍在可终止的 worker 内。

新建脚本默认 10000 ms，可设 50–60000 ms；旧脚本沿用原值，缺少选项仍为 1000 ms。时限覆盖网络等待。HTTP 事务与流程预览没有总时限，单次脚本超时独立保留。取消传到解码器、步骤循环和工作进程；超时/取消可强制终止工作进程，并取消仍在执行的辅助网络请求。代理全局最多 4 个脚本流程，试运行和真实脚本共用最多 4 个工作进程名额，满时报告错误，不堆积无界等待任务。正文、Header、脚本和匹配字符串没有新增应用层尺寸上限，沿用[当前限制策略](../LimitsAudit.md)。

普通 HTTP 的脚本或延迟所在方向等待完整 Body 后执行；没有脚本和延迟的方向保留现有流式路径。依据上游 Content-Type 自动识别的 SSE 在响应头阶段执行延迟；响应脚本位于 Body 替换之前时明确报错，位于替换之后时处理有限的替代内容，不等待无限流结束。步骤失败停止流程，请求阶段返回 400、响应阶段返回 502，并记录具体错误；尚未实现设计稿中的可选失败后继续策略。支持 await / Promise / fetch；独立 HTTP Call 步骤仍为后续能力。

回归覆盖 条件组、URL 分量、Query/Cookie、多 Header 与否定匹配、JSON 返回格式、重复 Header、空/null Body、大正文、死循环超时和取消，以及 TCP 回环真实请求/响应、Mock、分块上传、编码正文。工作区隐藏窗口检查覆盖分栏、标题、工具栏、收起重开和切页；不代表完整 App 的视觉或 Chrome 实测验收。

## 步骤详情与模板（2026-09-26）

步骤详情的输入框标题使用“Body · 文本”“参数值”“替换为”和“值”，不附加“模板”字样；辅助功能标签和格式化提示同步使用简洁文案。

“请求/响应阶段 · 第 N 步”作为“步骤详情”标题下方的 11 pt 次要注解，随阶段、选择和步骤排序同步更新，不再占用正文顶部一行。详情 footer 不再显示顶部分割线。macOS 26+ 将标题与 footer 放入原生分栏附件栏，表单滚动区域铺满详情面板并延伸到上下附件栏背后，由系统自动调整内容安全区；macOS 26.1+ 使用 soft 滚动边缘效果，滚动经过标题和按钮区域时呈现原生柔化效果。旧系统保留固定标题和 footer 布局。详情 footer 右侧保留红色玻璃“删除”按钮，点击后由原生 Popover 二次确认；取消、关闭弹层或切换步骤不会删除。详情不再提供上移、下移按钮，步骤排序继续使用流程列表。

“修改 Header”支持一个步骤内配置多个条目，每个条目使用独立原生区块，包含修改方法、名称、按方法显示的值与条目删除按钮，“Header 修改”添加按钮固定在 footer 左侧，使用原生玻璃样式（macOS 26+），不随条目列表滚动。名称保留候选选择和自定义输入，值使用模板文本编辑器。区块内容显式约束四边，短表单从滚动区域顶部显示，长列表可滚动至最后一项。步骤表单的外层滚动区域延伸到详情面板右边缘，右侧 20 pt 字段留白放在滚动文档内部，滚动条不覆盖 Header 区块；标题与 footer 保持原有边距。

`headers` 数组条目使用可选 `operation`（`add` / `modify` / `remove` / `set`），编辑器提供“添加”“修改”“删除”“添加或覆盖”四种方法。`set` 会先移除所有同名 Header（忽略大小写），再添加新值；没有同名 Header 时直接添加。旧 `set` 配置保持原有行为，也可以切换至其他方法。缺少操作的旧条目和旧单组 `name/value` 按原步骤类型读取，打开配置不自动改写。显式空数组不操作。整组先解析需要使用的值并校验，全部通过后再按顺序应用；删除和未匹配的修改忽略保存的值，非法名称、值或由代理维护的 Header 会报错，整步不部分应用。归档保留条目操作与内容。

支持模板的名称和值输入框用浅蓝色圆角背景标记完整的 `{{…}}` 文本。标记只影响显示，复制、保存、撤销仍操作原始文本；未闭合表达式保持普通文本。未知变量也会被标记，但执行时仍报告变量不存在。JavaScript 不进行模板展开，也不显示模板标记；脚本内继续使用 `env.api` 访问环境。

环境引用统一显示为 `{{$env.api}}`，执行时继续兼容已有 `{{env.api}}`。原有内置变量包括 `{{$uuid}}`（当前事务 UUID）和 `{{$timestamp}}`（当前事务时间的 Unix 秒数），同一事务内使用相同上下文。替换为环境值后不递归展开。

### 内置变量

下表变量已接入解析器和动态值 Popover，所有引用均使用 `{{$…}}`。日期时间统一为 UTC。请求开始时创建不可变快照，请求与响应阶段（包括脚本流程和本地预览）共用同一组随机值；不同请求重新生成。`$request.*` 始终读取修改前的请求。

| 变量 | 含义 / 格式 |
| --- | --- |
| `$timestampMs` | Unix 毫秒整数 |
| `$isoDateTime` | UTC ISO 8601，带毫秒与 `Z` |
| `$date` | UTC 日期 `yyyy-MM-dd` |
| `$time` | UTC 时间 `HH:mm:ss` |
| `$randomInt` | 0–999999 的整数 |
| `$randomFloat` | [0, 1) 小数，固定 `.` 小数点 |
| `$randomBoolean` | `true` / `false` |
| `$randomString` | 16 位大小写字母与数字 |
| `$randomHex` | 32 位小写十六进制字符串 |
| `$request.method` | 原始请求方法 |
| `$request.url` | 原始完整 URL |
| `$request.host` | 原始 URL 主机，不含端口 |
| `$request.path` | 原始 URL 路径，保留百分号编码；不含查询字符串，空路径为 `/` |
| `$response.status` | 进入响应阶段时的状态码，后续修改状态码不改变该值；Mock/本地重定向使用其生成的状态码，仅响应阶段可用 |

随机数的范围和长度按上表固定。`$uuid` 保持事务标识语义，不会在每次引用时重新生成。请求阶段引用 `$response.status` 会明确报错，动态值 Popover 仅在响应步骤中提示该变量。环境值保持单次替换，不递归展开其中的模板。

Header、查询参数与 URL 的模板文本采用至少 24 pt 的行高，为 20 pt 标记上下各留 2 pt 空白，显式换行与自动折行均保留至少 4 pt 的标记间隔。排版基线按该行实际字形居中，避免末行或不同字符组合的标记被压缩。标记按实际字形轮廓垂直居中，左右保留 4 pt，背景高度以 20 pt 或字形高度加 4 pt 的较大值为目标，并围绕中心对称限制在行高内。短值编辑器为 72 pt，可完整显示两行。背景裁切在文本容器内；浅蓝背景不透明度为 20%，圆角为 5 pt。光标宽度为 2 pt，按字体的升部与降部高度缩短并在行内垂直居中，不改变行高与行间距。保留原生纯文本选择、复制和撤销。

步骤详情左下角的添加按钮右侧提供独立 info 按钮，使用 24 × 24 pt 原生圆形 `NSButton`、regular 控件尺寸与 13 pt 图标，和添加按钮垂直居中对齐；macOS 26+ 使用控件自身的 `.glass` 样式；两个按钮间保留 12 pt 间隔，各自显示独立外观。没有添加操作的步骤将 info 保留在左下角。点击打开宽 340 pt 的 transient Popover，为右侧复制按钮保留空间；内置变量和当前环境变量各占一行，行高为 28 pt。悬停该行时，右侧复制按钮以 150 ms 淡入淡出；减少动态效果时即时切换，键盘聚焦复制按钮时同样显示。复制得到完整 `{{$变量名}}` 模板，不是解析后的值。重建表单、切换步骤、收起侧栏或关闭窗口时关闭弹层。详情表单不再常驻动态值清单。

模板与普通文字边界通过文字排版属性预留间距，背景外仍保留可见空隙，不向字符串插入空格；相邻模板分别预留边界，复制、保存、撤销和执行内容保持原文。普通文字后、模板前的光标贴合普通文字末尾，装饰间距不计入光标位置；点击定位与输入法候选位置同步，换行起始位置保持系统行为。

手动收起步骤详情后，点击请求或响应阶段中的步骤会重新展开详情，包括再次点击当前已选中的步骤。普通内容刷新保留手动收起状态；展开中的详情重复点击不会被切换为收起。

## SSE 响应

编辑页不再提供 SSE 复选框，也不自动插入响应 Header 步骤；旧配置中的 `RequestWorkflow.isSSE` 和已有 Header 步骤保留。代理根据上游原始响应 Content-Type 自动识别 SSE，`isSSE` 标记不再作为执行开关，请求或响应 Header 的手动修改不触发协议转换。已识别的 SSE 替换 Body（含本地文件）取消上游并产生有限替代响应；延迟在响应头阶段执行。整流脚本仅可放在替换 Body 之后，事件与消息脚本暂未实现。见 [持续捕获](streaming-capture.md)。


## 修改 JSON

请求和响应阶段的添加菜单均提供“修改 JSON”。配置沿用多 Header 的逐条 `NSBox` 表单，包含修改方法、路径、JSON 值和移除按钮，footer 提供“添加 JSON 修改”。删除操作隐藏值但保留草稿。解析模板开关作用于路径和值；值必须是完整 JSON，字符串需双引号，数字、布尔、对象、数组、`null` 保留类型。模板先按现有文本规则展开，再校验 JSON；字符串中的引号等字符需使用 JSON 转义。

路径使用 `data.user.name`、`items[0].name`；数组根使用 `[0]`，含点、空格、括号或空名称的对象键使用 `["a.b"]`、`[""]`，引号遵循 JSON 转义。名称区分大小写，下标从 0 开始，不支持通配符、负数或整根替换；整根替换使用“替换 Body”。

- 添加或覆盖：覆盖已有目标或添加最后一级字段，父对象必须存在；数组只允许覆盖已有下标或在等于数组长度的下标追加，不补空位。
- 修改：只修改已有目标；路径未命中时跳过，不解析无用的值。
- 删除：移除已有字段或数组元素，数组后续元素前移；未命中时跳过，不解析值。

条目按顺序作用于前一条的结果，路径类型冲突、路径命中重复键、无效 JSON 或模板失败时整步不提交，停止当前流程并记录失败；此前成功的步骤保留。空条目列表不读取 Body。解析为保留数字原文、字符串转义和对象字段顺序的树，限制递归深度为 128 层；发生修改后输出紧凑 JSON，原始缩进空白不保留。无实际变化时保留原始字节和 Header。

`JSONBodyProcessor` 通过现有完整 Body 和后台执行契约接入代理；上游 gzip / zlib-wrapped deflate 沿既有解码路径处理，修改成功清除旧编码、摘要、范围与缓存校验 Header，长度与传输编码由代理重建，不自动更改 Content-Type。前置替换 Body、JSON 修改、脚本和 Mock 的结果可继续修改；前置 Base64 替换需为未压缩 UTF-8 JSON。非 JSON、空 Body、损坏压缩、未知编码或非 UTF-8 正文报错。SSE 只能在有限 Body 替换后使用，不能读取无限事件流；WebSocket 握手响应仍只支持 Header 步骤。

`ModificationStep.jsonEdits` 随工作区和规则归档保存，旧步骤缺失该字段不改变行为。验证包含 Core 的类型保留、路径边界、连续操作与回滚，代理 TCP 回环的分块请求、压缩响应和 Mock，以及隐藏 AppKit 表单的双阶段入口、编辑、增删、禁用和滚动边界。隐藏窗口不等同于完整 App 视觉或浏览器验收。
