# 请求修改配置（2026-09-26）

采用用户选定的方案 1，并合入 URL / Host 匹配与脚本 API 补充；[修订设计稿](request-modification-v3.png) 使用内置 Image Gen 生成。设计稿为布局参考，当前实现的控件外观由 macOS 系统绘制，执行契约以下文为准。

## 匹配测试

匹配条件第一行右侧提供原生“测试匹配”按钮，点击打开独立 Sheet；主页面不展开内嵌测试区。对话框展示当前规则的只读条件摘要，测试请求可选择方法、输入完整 HTTP/HTTPS URL；启用 Header 条件时可增删示例 Header，支持同名多项。测试 URL 输入框按回车会提交当前输入并触发测试；输入法组字时回车仍用于确认候选。测试输入只保留在本次对话框中，不改写规则、不发送请求、不运行步骤。对话框主体直接使用原生布局，不提供上下滚动；高度随条件、示例 Header 和测试结果撑开或收缩，避免无 Header 时留下大块底部空白。“完成”在 macOS 26+ 使用原生 `.glass` 胶囊按钮，旧系统保留标准按钮。

测试在后台复用 `WorkflowMatcher`，沿用 URL 大小写、Host 提取与大小写、通配符整串匹配、正则查找和同名任一 Header 满足的语义及正则时间预算。结果逐项展示请求方法、URL / Host 与 Header 的匹配状态；地址结果高亮首次命中范围，Header 列出期望与实际值或缺失原因。无效规则显示“无法测试”并禁用测试按钮，无效示例与普通未匹配分开显示。编辑输入立即清空旧结果，过期的后台结果不回填。

测试只判断条件，不考虑项目/规则启用状态与其他规则优先级；已停用规则在对话框中明确提示，条件满足不表示捕获时会执行。原有“预览流程”入口保留。`WorkflowMatchTestTests` 检查匹配一致性与错误分类，规则隐藏窗口回归检查布局和交互；完整 App 的 Sheet 外观与真实键盘操作仍需人工验收。

## 窗口和编辑

请求编辑区域从请求名称开始，不在名称上方重复显示所属项目名。

左侧以项目分组，项目名称和条目数在组标题，请求修改显示名称、方法和匹配值，停用条目降为次要视觉。底部保留原生圆形加号和搜索；加号继续提供添加请求、添加项目。中间是名称/启用、匹配条件，以及并排的请求阶段和响应阶段。步骤可拖动排序，也可在详情中上移、下移、停用和删除。

匹配条件按请求方法、地址和 Header 分组，组间使用系统分隔线。每个阶段的步骤列表与添加菜单共用浅灰圆角边框；步骤使用独立淡灰圆角背景。选中步骤使用浅蓝背景、细蓝边框和左侧蓝色标记，文字保持正常前景色；这部分按确认的设计设置，不采用列表默认的实色选中高亮。列表保留拖动排序、上下方向键选择、原生按钮可访问性与右键操作。

点击任一步骤后使用 `WorkspaceSplitController` 的窗口级原生 Inspector，标题为“步骤详情”，由标题栏最右侧按钮收起或重开。手动收起保留步骤选择；删除或切换到没有有效步骤的条目后关闭。请求日志继续使用同一分栏容器，但显示请求详情和日志专属工具栏，不显示步骤操作。

匹配区域参考 Finder 搜索条件，顶部标明“满足以下所有条件”，原生 `NSBox` 内按请求方法、URL / Host、Header 分为三组，以系统分隔线分开。方法独占第一行；地址目标、条件与值位于第二组同一行；Header 作为第三组独立开关。地址目标下拉宽 130 pt，条件下拉宽 90 pt，方法下拉宽 105 pt；方法与地址条件下拉的左侧对齐；地址和 Header 匹配值保持单行，窄窗口下编辑内容横向滚动，不折行；字段保留原生交互。普通说明移至悬停提示，仅无效输入显示行内错误。Header 名称保留 240 pt，常规宽度下名称、条件和值同排，窄窗口在该组内换行，匹配值至少保留 100 pt。

步骤卡片固定 56 pt 高，序号、文字和停用图标垂直居中；标题与摘要各一行，截断内容通过系统悬停提示查看。选中时左侧蓝色竖线跟随卡片全高，并沿卡片圆角裁切。列表每项上下各留 4 pt，不另加行间距或垂直内容边距，列表高度按相同尺寸计算，超过 400 pt 后滚动。请求与响应阶段的滚动区域延伸到外框内侧，滚动条贴右边；16 pt 水平留白放在步骤卡片和添加按钮内部。

菜单中的 11 种修改类型使用语义对应的 SF Symbol，统一显示在添加步骤菜单、步骤卡片的类型名称前和详情标题前。Header 修改使用调节图标，Body 使用文档、目标地址使用链接、查询参数使用调节图标、URL 替换使用循环箭头、请求方法使用双向箭头、状态码使用数字、静态数据使用文档副本、重定向使用转向箭头、脚本使用代码符号、延迟使用时钟。类型名称继续保留，图标不重复加入辅助功能朗读。

macOS 27 默认可能隐藏菜单项图片，添加步骤菜单显式设置原生 `preferredImageVisibility = .visible`，确保类型图标显示；旧系统继续使用 `NSMenuItem.image`。

Header 步骤统一命名为“修改 Header”，添加菜单仅保留一个入口。条目下方不展示添加、修改、删除及旧配置的操作说明。每条 Header 独立选择“添加”、“修改”或“删除”，同一步内可混用并按顺序执行；删除时隐藏值，切回时保留已输入值。添加始终追加一条，保留已有同名项；修改按不区分大小写的名称匹配已有项，更新所有匹配项的值并保留原名称、数量和顺序，没有匹配时跳过；删除移除全部同名项，不存在时跳过。新步骤序列化标识仍为 `setHeader`，旧 `removeHeader` 步骤同样以统一编辑器打开并保留删除行为。名称采用可编辑的原生 `NSComboBox`，可以从候选列表选择，也可输入完整自定义名称。候选项来自浏览器扩展 `ModifyHeadersRuleDetail.tsx` 的 `COMMON_HEADERS`，macOS 所有 Header 下拉框按不区分大小写的字母顺序展示。`Content-Length`、`Host` 等候选仍保留以便两端列表一致，但选择后明确提示其由代理维护，执行时继续拒绝非法改写。参见 [Apple NSComboBox](https://developer.apple.com/documentation/appkit/nscombobox)。

## 请求方法修改

“修改请求方法”的字段标题为“请求方法”，使用原生 `NSPopUpButton` 从 [IANA 注册的 HTTP 方法](https://www.iana.org/assignments/http-methods/) 中选择，常用方法排在前面。候选列表暂不包含当前不支持改写的 CONNECT、TRACE，以及 HTTP/2 连接前言专用的 PRI；不提供通配符。旧配置中不在候选列表内的方法或模板仅保留显示与原值，不能重新选择，只有主动选择候选方法才替换；空值显示“请选择请求方法”。选择后沿用步骤自动保存。

## Body 编辑

“替换 Body”和 Mock 的原生文本编辑区填满窗口剩余高度，最低 360 pt；窗口较小时外层表单可滚动。文本视图按内容增长，长内容在编辑区内纵向滚动。显示逻辑行号（自动折行不增加行号）、JSON 键名、字符串、数字、布尔值及符号着色，保留模板变量标记。颜色跟随系统明暗外观，仍可输入任意纯文本。

Body 编辑器、请求日志的请求体 / 响应体 JSON 树和原始数据共用 `JSONSyntax`：key 蓝色、字符串绿色、数字橙色、布尔值和 `null` 紫色，结构符号使用次要文字色。原始数据着色不修改内容；搜索匹配继续使用背景高亮，树形选中行保留系统选中文字色。模板变量标记仅用于编辑器，Header 名称保持默认文字色。

“格式化 JSON”接受标准 JSON，以及 key 为未加引号的标识符、对象或数组末项带逗号的写法，例如 `{name: "张三",}`。仅在点击时将 key 补为双引号、移除末尾逗号，并使用两空格缩进和换行；保留字段顺序、数字原文、字符串转义及模板变量，支持撤销。字符串内模板原样保留，未加引号且作为完整值的模板按占位值检查结构；这不代表模板展开后的 JSON 一定有效。解析不执行 JavaScript 表达式；不支持的内容或语法不完整时显示提示并保留输入。着色与行号只影响显示；Body 仍按文本 / 模板整体替换，不自动修改 Content-Type。

## URL 修改步骤

“改写请求 URL”修改代理实际访问的地址，保留请求方法和 Body；“返回重定向”返回 3xx 状态码和目标地址，由客户端发起新请求。添加菜单、步骤标题和详情共用这两个名称，配置区显示对应说明；序列化标识仍为 `rewriteURL` 和 `redirect`，执行行为不变。

请求阶段新增“修改查询参数”和“替换 URL 字符串”，与其他步骤按顺序作用于当前 URL，命中日志保留对应类型。两项均支持多个配置区块、环境变量与动态模板，响应阶段不提供。

- 修改查询参数：参数配置区域使用独立的原生表单区块，每条选择添加、修改或删除，按显示顺序执行；添加遇到同名跳过，修改仅更新已有的全部匹配参数，删除移除全部匹配参数、未匹配时跳过。添加和修改显示名称和值，删除仅显示名称，切回时保留已输入值。支持增删条目与空列表，空列表不操作；配置通过 `queryParameters` 保存。名称区分大小写，空值保留 `name=`，名称和值按 UTF-8 URL 编码，未修改参数的原始编码、顺序和重复项保持不变，`+` 视为加号。整组成功后才更新 URL；删除及无需执行的添加/修改不解析未使用的值。旧 name/value 配置保留原有“不存在时追加、同名覆盖合并为一项”行为，表单显示兼容说明，显式选择操作后采用新语义。标题、启用开关和步骤删除区域保持不变。
查询参数的执行语义、名称大小写与 URL 编码说明统一放在标题下方，使用与修改 Header 相同的次要说明样式；条目内部和添加按钮下方不再重复显示说明。存在旧配置时兼容说明也合并在标题下方，选择新操作或匹配规则后同步移除。

参数名称使用原生单行输入框，长内容横向滚动，回车提交并结束编辑；参数值继续使用多行编辑器。

修改与删除的操作行提供参数名称匹配规则：等于、包含、通配符、正则，默认等于；添加时隐藏并忽略匹配规则，切回修改或删除时保留选择。规则保存在每条参数的 `matchRule`，旧条目缺省按等于读取。匹配 URL 解码后的参数名称，默认区分大小写；通配符整名称匹配（`*` 任意字符序列、`?` 单个字符），正则沿用现有匹配器的查找语义，可用锚点限制全名。修改只更新所有匹配参数的值，保留各自名称及名称原有编码；删除移除全部匹配参数。无效正则拒绝整组操作，不保留前面条目的部分修改。

- 替换 URL 字符串：每个配置使用独立原生表单区块，可添加、删除；查找字符串使用单行输入框，替换值保留动态模板编辑器。区分大小写说明置于步骤标题下方。每块按原文强制替换整个 URL 中的全部匹配，不使用正则，也不提供仅替换首项的选项；后续区块作用于前面替换后的 URL，同一区块不会再次匹配自己生成的内容。查找字符串不能为空，替换为空会删除匹配内容；未匹配时保持 URL 不变。通过 `urlReplacements` 保存，缺省时读取旧 `name/value` 单组配置，显式空列表不操作。每块替换后校验 URL，整组成功后才更新请求；失败不留下半组修改。

两项完成后校验最终 HTTP/HTTPS 地址；无效结果报错，不写入当前 URL，也不计入成功执行步骤。步骤卡片展示参数赋值或替换关系。Core 测试覆盖编码、重复项、执行顺序、模板、保存恢复与失败；回环代理测试检查上游实际收到的路径和日志中的最终 URL，不能代替浏览器验收。

## 响应延迟

响应阶段的“添加步骤”提供“添加延迟”，详情使用原生单行输入框，单位为 ms，默认 1000。时间为非负整数，0 立即继续；空值、负数、小数和超出整数范围的值显示错误，执行时拒绝。步骤卡片显示“等待 N ms”。延迟沿用步骤启停、排序、复制和配置保存，不提供请求阶段入口。

流程到达延迟步骤时异步等待，等待完成才记录该步成功并执行后续步骤；连续延迟依次累加。普通上游响应与 Mock 响应均生效，本地预览执行相同等待。含延迟的响应沿用后台完整 Body 流程，完成全部响应步骤后才向客户端发送响应头和正文；仅含延迟时不解码文本、不占用脚本执行名额，原始二进制和压缩内容保留。等待使用单调时钟，不阻塞网络线程或主线程。

HTTP 请求事务和流程预览不设总时限，超过 30 秒的延迟仍会等满后继续下一步。客户端断开、停止捕获或关闭预览时取消等待，不执行下一步，也不把未完成的延迟记录为成功。含延迟或脚本的持续响应仍需等到完整 Body 才执行步骤。

## 匹配

匹配目标仍为 URL / Host 二选一；Header 是独立、可启用的附加条件。勾选 Header 条件后，依次填写名称、独立的匹配规则和值，名称输入框宽 240 pt，匹配值使用剩余空间，窄窗口在 Header 组内换行；地址条件、Header 条件和 HTTP 方法必须同时满足才命中。例如 URL 等于某个地址，并且 `X-Environment` 等于 `staging`。关闭 Header 条件时仅按地址与方法匹配，保留已填写的 Header 配置；输入区收起为复选框一行，分组底部保留 12 pt 内边距，保留输入区横向约束以保持窗口和分栏宽度。

Header 支持等于、包含、通配符和正则，匹配客户端原始请求头，在修改步骤之前执行。名称不区分大小写，值区分大小写；缺失时不命中，同名多项中任意一项符合即可，不拼接值。启用时，非法或空名称、空匹配值和无效正则不会命中，并在编辑器提示。流程预览使用“请求与响应输入”中的请求 Header，与代理采用同一联合匹配逻辑。

Header 条件独立保存为 `matchHeaderEnabled`、`matchHeaderName`、`matchHeaderRule` 和 `matchHeaderPattern`。旧配置缺少字段时默认关闭，不影响 URL / Host 匹配或旧前缀迁移。此前保存的 Header 单独匹配配置会迁移为 URL 通配符 `*` 加原 Header 条件，保留原有行为，之后可进一步限定地址。

| 配置 | 行为 |
| --- | --- |
| 目标 | URL 匹配：完整绝对 URL；Host 匹配：解析后的主机名，不含协议、端口、路径、查询参数 |
| 通配符 | 整体匹配，`*` 为任意长度、`?` 为一个字符；其余字符按字面量处理 |
| 正则 | ICU 正则搜索，可使用 `^` / `$` 限定范围；无效表达式在编辑器显示错误、不命中 |
| 等于 / 包含 | 字符串全等 / 子串匹配 |
| 大小写 | URL 区分大小写，Host 不区分大小写并去除末尾域名点 |
| 方法 | 全部，或指定 HTTP 方法；多个命中仍按项目顺序选择首个启用流程 |

不再提供前缀选项。空匹配值不命中。旧 `urlPrefix` 解码为 URL 正则 `\A` + 转义后的原值，保留旧配置的字面量前缀语义（包括 `?`、`*` 等字符）。工作区保存版本提升为 2，加载接受 1 和 2；旧版本 App 会拒绝版本 2，避免静默覆盖新字段。

## 脚本 API

两个阶段的“添加步骤”均包含“执行脚本”。代码为同步 JavaScript 函数体，请求阶段必须返回 `request`，响应阶段返回 `response`（也可返回具有同样结构的新对象）。脚本不作模板展开，环境变量通过 `env.name` 读取。

执行失败说明统一显示在步骤标题下方，步骤备注使用白色输入背景。脚本代码编辑器提供 JavaScript 关键字、字符串、模板字符串、注释、数字和函数调用高亮，以及随滚动同步的逻辑行号；自动换行不重复编号，颜色不写入脚本文本或撤销记录。脚本编辑器仅保留“试运行”入口，点击后打开 900 × 620 pt 对话框，不立即执行。左侧编辑示例输入，右侧显示只读结果；底部“运行”使用当前输入执行脚本，错误也在同一区域展示。输入变化后取消在途运行并提示重新运行，关闭时取消执行，重新打开保留本次编辑器会话中的输入。编辑页不再显示独立的示例输入按钮、运行结果或分段切换。

所有步骤详情右下角的删除按钮使用红色图标和文字。步骤备注采用支持白底的原生文本框边框样式；流程预览中的“请求与响应输入”保持 600 × 540 pt，“预览流程”保持 680 × 500 pt。输入表单在固定窗口内滚动，滚动条遵循系统显示偏好；试运行左右编辑区等宽，与中间分隔线各留 24 pt，左侧滚动条位于这段间隔内，显示或隐藏都不改变字段边缘；长 URL 在单行输入框内滚动。左侧 Header 与 Body 多行输入使用 8 pt 圆角，聚焦时显示 AppKit 系统焦点环，失焦后消失；滚动视口为左侧和底部焦点环预留绘制空间，字段位置与列间距不变；聚焦 Header 或 Body 输入框时，外层表单滚动到完整显示输入框及焦点环的位置。右侧结果保持只读。

```ts
type Header = { name: string; value: string };
type Request = {
  method: string;
  url: string;
  headers: Header[];
  body: string | null;
};
type Response = {
  status: number;
  headers: Header[];
  body: string | null;
};
// 每次执行注入：
request: Request;
response: Response | null;
env: Record<string, string | number | boolean | unknown[] | Record<string, unknown>>;
```

请求阶段 `request` 是之前步骤处理后的请求，`response` 为 `null`。响应阶段 `request` 是只读的发出请求快照，`response` 是之前步骤处理后的响应。`env` 始终只读。Header 使用数组，保留大小写与重复项（例如多个 `Set-Cookie`）；比较名称时忽略大小写。

`body` 为完整 UTF-8 文本，JSON 也以字符串提供，使用 `JSON.parse` 和 `JSON.stringify` 处理。gzip / zlib-wrapped deflate 在后台解码；不支持的编码、损坏压缩或非 UTF-8 内容为 `null`。空正文是 `""`。返回 `null` 保留已有正文，返回空字符串清空正文；仅当文本实际改变时替换正文并清除原编码、摘要、范围与缓存校验 Header，代理重建 Content-Length / Transfer-Encoding。未修改的压缩和二进制正文原样转发。

```js
// 请求阶段
request.headers.push({ name: "X-API-Key", value: env.apiKey });
return request;

// 响应阶段
const data = JSON.parse(response.body);
data.debug = true;
response.body = JSON.stringify(data);
return response;
```

`method` 不支持 CONNECT / TRACE，`url` 必须为无用户信息及片段的完整 HTTP/HTTPS 地址，`status` 为 200–599 整数。Host、Content-Length、Transfer-Encoding、Connection、Upgrade、Trailer 可读取但不能由脚本改写。所有返回字段校验成功后才提交草稿，失败不会部分提交脚本结果。

“API 帮助”在编辑器内展示相同结构、格式和示例。“示例输入”可编辑请求 URL、方法、Header JSON 数组、请求文本，以及响应状态、Header、文本；“试运行”使用当前环境和真实脚本执行器，显示 JSON 结果或错误，不发送请求。“预览流程”另校验真实测试 URL 是否命中，再按顺序执行两阶段。

## 执行与验证边界

使用系统 [JavaScriptCore](https://developer.apple.com/documentation/javascriptcore/jscontext) 和一次一脚本的独立进程；App 同一可执行文件通过专用参数进入工作模式，在创建 NSApplication 之前返回，SwiftPM 测试使用独立 worker target。没有导出原生对象、文件、网络、DOM、Node.js API 或定时器；不支持 Promise 返回值。

脚本默认 1000 ms，可设 50–5000 ms。HTTP 事务与流程预览没有总时限，单次脚本超时独立保留。取消传到解码器、步骤循环和工作进程；工作进程每 25 ms 检查取消，超时/取消可强制终止。代理全局最多 4 个脚本流程，试运行和真实脚本共用最多 4 个工作进程名额，满时报告错误，不堆积无界等待任务。正文、Header、脚本和匹配字符串没有新增应用层尺寸上限，沿用[当前限制策略](../LimitsAudit.md)。

脚本或延迟所在方向等待完整 Body 后执行；没有脚本和延迟的方向保留现有流式路径。持续流（例如 SSE）不适合完整 Body 流程：正文不结束时，步骤会一直等待。步骤失败停止流程，请求阶段返回 400、响应阶段返回 502，并记录具体错误；尚未实现设计稿中的可选失败后继续策略。本轮支持同步脚本，辅助 HTTP API 和异步脚本仍为后续能力。

回归覆盖 URL/Host 四类匹配、旧前缀迁移、JSON 返回格式、重复 Header、空/null Body、大正文、死循环超时和取消，以及 TCP 回环真实请求/响应、Mock、分块上传、编码正文。工作区隐藏窗口检查覆盖分栏、标题、工具栏、收起重开和切页；不代表完整 App 的视觉或 Chrome 实测验收。

## 步骤详情与模板（2026-09-26）

步骤详情的输入框标题使用“Body · 文本”“参数值”“替换为”和“值”，不附加“模板”字样；辅助功能标签和格式化提示同步使用简洁文案。

“请求/响应阶段 · 第 N 步”作为“步骤详情”标题下方的 11 pt 次要注解，随阶段、选择和步骤排序同步更新，不再占用正文顶部一行。详情底部只保留红色“删除”按钮，点击后由原生 Popover 二次确认；取消、关闭弹层或切换步骤不会删除。详情不再提供上移、下移按钮，步骤排序继续使用流程列表。

“修改 Header”支持一个步骤内配置多个条目，每个条目使用独立原生区块，包含修改方法、名称、按方法显示的值与条目删除按钮，添加按钮放在列表外。名称保留候选选择和自定义输入，值使用模板文本编辑器。区块内容显式约束四边，短表单从滚动区域顶部显示，长列表可滚动至最后一项。

`headers` 数组条目使用可选 `operation`（`add` / `modify` / `remove`）；旧 `set` 继续保持添加或覆盖行为，编辑器以禁用的“添加或覆盖（旧配置）”选项显示，显式选择新方法后切换语义。缺少操作的旧条目和旧单组 `name/value` 按原步骤类型读取，打开配置不自动改写。显式空数组不操作。整组先解析需要使用的值并校验，全部通过后再按顺序应用；删除和未匹配的修改忽略保存的值，非法名称、值或由代理维护的 Header 会报错，整步不部分应用。归档保留条目操作与内容。

支持模板的名称和值输入框用浅蓝色圆角背景标记完整的 `{{…}}` 文本。标记只影响显示，复制、保存、撤销仍操作原始文本；未闭合表达式保持普通文本。未知变量也会被标记，但执行时仍报告变量不存在。JavaScript 不进行模板展开，也不显示模板标记；脚本内继续使用 `env.api` 访问环境。

环境引用统一显示为 `{{$env.api}}`，执行时继续兼容已有 `{{env.api}}`。原有内置变量包括 `{{$uuid}}`（当前事务 UUID）和 `{{$timestamp}}`（当前事务时间的 Unix 秒数），同一事务内使用相同上下文。替换为环境值后不递归展开。

### 内置变量

下表变量已接入解析器和动态值 Popover，所有引用均使用 `{{$…}}`。日期时间统一为 UTC。请求开始时创建不可变快照，请求与响应阶段（包括脚本流程和本地预览）共用同一组随机值；不同请求重新生成。`$request.*` 始终读取修改前的请求。

| 变量 | 含义 / 格式 |
| --- | --- |
| `$timestampMs` | Unix 毫秒整数 |
| `$isoDateTime` | UTC ISO 8601，带毫秒与 `Z` |
| `$date` | UTC 日期 `yyyy-MM-dd` |
| `$time` | UTC 时间 `HH:mm:ss` |
| `$randomInt` | 0–999999 的整数 |
| `$randomFloat` | [0, 1) 小数，固定 `.` 小数点 |
| `$randomBoolean` | `true` / `false` |
| `$randomString` | 16 位大小写字母与数字 |
| `$randomHex` | 32 位小写十六进制字符串 |
| `$request.method` | 原始请求方法 |
| `$request.url` | 原始完整 URL |
| `$request.host` | 原始 URL 主机，不含端口 |
| `$request.path` | 原始 URL 路径，保留百分号编码；不含查询字符串，空路径为 `/` |
| `$response.status` | 进入响应阶段时的状态码，后续修改状态码不改变该值；Mock/本地重定向使用其生成的状态码，仅响应阶段可用 |

随机数的范围和长度按上表固定。`$uuid` 保持事务标识语义，不会在每次引用时重新生成。请求阶段引用 `$response.status` 会明确报错，动态值 Popover 仅在响应步骤中提示该变量。环境值保持单次替换，不递归展开其中的模板。

模板文本采用至少 24 pt 的行高，为 20 pt 标记上下各留 2 pt 空白，显式换行与自动折行均保留至少 4 pt 的标记间隔。排版基线按该行实际字形居中，避免末行或不同字符组合的标记被压缩。标记按实际字形轮廓垂直居中，左右保留 4 pt，背景高度以 20 pt 或字形高度加 4 pt 的较大值为目标，并围绕中心对称限制在行高内。短值编辑器为 72 pt，可完整显示两行。背景裁切在文本容器内；浅蓝背景不透明度为 20%，圆角为 5 pt。光标宽度为 2 pt，按字体的升部与降部高度缩短并在行内垂直居中，不改变行高与行间距。保留原生纯文本选择、复制和撤销。

右侧栏展开且处于请求修改页时，收起按钮左侧提供独立的 info 玻璃按钮（与收起按钮均使用原生 `NSToolbarItem`，启用 `isBordered`，在 macOS 26+ 显示系统玻璃背景；两者之间保留原生固定间隔，形成两个独立玻璃按钮）。点击打开宽 340 pt 的 transient Popover，为右侧复制按钮保留空间；内置变量和当前环境变量各占一行，行高为 28 pt。悬停该行时，右侧复制按钮以 150 ms 淡入淡出；减少动态效果时即时切换，键盘聚焦复制按钮时同样显示。复制得到完整 `{{$变量名}}` 模板，不是解析后的值。切换步骤、页面或收起侧栏时关闭弹层。详情表单不再常驻动态值清单。

模板与普通文字边界通过文字排版属性预留间距，背景外仍保留可见空隙，不向字符串插入空格；相邻模板分别预留边界，复制、保存、撤销和执行内容保持原文。普通文字后、模板前的光标贴合普通文字末尾，装饰间距不计入光标位置；点击定位与输入法候选位置同步，换行起始位置保持系统行为。

手动收起步骤详情后，点击请求或响应阶段中的步骤会重新展开详情，包括再次点击当前已选中的步骤。普通内容刷新保留手动收起状态；展开中的详情重复点击不会被切换为收起。
