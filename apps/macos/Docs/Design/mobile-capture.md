# 局域网手机抓取

## 使用步骤

1. Mac 与手机连接可互通的局域网。Mac 可使用 Wi-Fi 或有线；路由器不能隔离两台设备，防火墙需允许 Requestman 入站连接。
2. 设置 → 通用选择“仅启动代理”，开启“允许局域网设备连接”。从主窗口启动捕获；全局接管、浏览器模式也可开启局域网。
3. 点击主窗口标题栏右侧的手机图标（`iphone.gen3`），选择手机可访问的网卡地址。手机在当前 Wi-Fi 设置中选择手动 HTTP 代理，填写 Mac 的 IP 与端口（默认 9090），不填写协议或路径。
4. 在 Mac 点击“设置证书…”完成既有证书配置，再用手机扫码打开本地引导页。
5. iPhone 用 Safari 下载描述文件，在“通用 → VPN 与设备管理”安装，再到“通用 → 关于本机 → 证书信任设置”为 Requestman Local CA 开启完全信任。参见 [Apple 证书信任说明](https://support.apple.com/zh-cn/102390)。
6. Android 下载 `.cer`，在系统的安装证书入口选择 CA 证书。针对 API 24 及以上的 App 默认不信任用户 CA；自有 App 可配置调试专用 CA，参见 [Android 网络安全配置](https://developer.android.com/privacy-and-security/security-config)。
7. 发起请求，在日志与详情中查看设备来源。使用结束后，将手机 Wi-Fi 代理恢复为关闭。

“连接手机”图标仅在局域网监听实际生效、监听端口存在且不处于启停或重配期间出现，适用于全局接管、仅启动浏览器和仅启动代理三种模式；仅开启设置不会显示入口。停止监听后隐藏，重配失败按实际恢复的监听状态显示。右侧栏收起时位于其开关左侧，两者用原生工具栏间距分开，不合并为同一个按钮组；展开后保留在主内容区标题栏右侧。设置页不再提供重复入口。

连接引导使用紧凑的原生 AppKit 三步表单，无滚动区。“服务器（这台 Mac）”选择本机网卡地址，显示系统网卡名称，并与只读端口并排；刷新按钮重新读取地址。证书就绪后展示 96 pt 二维码和“复制安装链接”；未就绪时显示“设置证书…”入口，用户点击后复用现有证书流程。监听失效时清除二维码与链接，不保留二维码空位。兼容性、网络排查、设备别名与结束使用说明收纳在“连接帮助”Popover。Mac 代理启动状态不表示手机已连接或已信任证书。

## 监听与上游

默认仅绑定 `127.0.0.1`；局域网开启后绑定 `0.0.0.0`，保留同端口的回环入口。首版引导提供 IPv4 地址，刷新按钮重新读取接口地址；地址变化后需更新手机设置。二维码和复制内容中的端口使用实际监听端口，配置切换中或局域网未生效时不展示有效二维码。

`proxyOnly` 不启动浏览器或接管 Mac 系统代理。启动方式只对下一次启动生效，当前模式固定到会话结束。端口或监听范围变化会关闭已有连接并重启；失败时恢复旧配置。上次全局捕获的系统代理恢复失败仍阻止新会话绕过恢复。

手机与本机共用当前 HTTP 上游设置：手机 → Requestman → HTTP 上游（例如 Mac 上的 Surge）→ 目标。上游地址从 Mac 访问，`127.0.0.1` 指 Mac 自身；HTTP 使用绝对 URL，HTTPS 使用上游 CONNECT，解密后继续验证目标 TLS。关闭上游时使用系统网络路由，不读取手机的代理配置，也不修改 Surge 设置。不能把上游配置为 Requestman 自身的地址与监听端口，域名解析后的自循环也被拒绝。

## 公开证书分发

同一监听端口提供 `/requestman` 引导、`/requestman/ca.cer` DER 下载和 `/requestman/ios.mobileconfig` 描述文件。只匹配本机监听地址；路径请求绕过捕获与规则，上游不可用也不影响本地引导处理。端点不提供工作区、日志或其他文件，不生成证书或请求钥匙串授权；返回 `Cache-Control: no-store`，停止监听即停止分发。

描述文件只包含公开根证书，不配置 Wi-Fi 或 VPN。手机必须自行完成证书安装与信任；Mac 的信任结果不能代表手机已信任。证书尚未生成、无效或过期时明确失败。CA 私钥仍由 Mac 钥匙串持有，不进入下载、文件或日志。

## 设备来源与别名

来源取自下游 TCP 连接的远端 IP，不信任客户端提交的 HTTP Header。忽略临时源端口，IPv4-mapped IPv6 规范化；回环统一标识为 `local`、显示“本机”。缺少来源的旧日志显示“未知设备”，不能设置别名。

日志以“设备来源”列替换“环境”列，详情增加来源按钮。两个入口共用原生 `NSPopover` 与别名编辑器，支持保存、输入法安全的 Return 和清除；别名首尾去空白、最多 80 个字符。`deviceAliases` 随工作区及全量配置备份保存，旧工作区默认为空；环境仍作为请求执行快照保存在记录中。

已有、后续和打开文件中具有同一来源的日志均从映射取显示名，因此改名后统一更新。别名不逐条写入日志文件；日志保留来源 IP，在另一工作区中使用该工作区的别名。IP 是接入来源而非永久设备身份，DHCP 更换 IP 或其他设备复用 IP 时需要调整别名。

## 验证边界

包测试覆盖旧配置/日志兼容、来源持久化、局域网 HTTP 与上游、HTTPS 上游解密、证书下载绕过规则和上游、独立会话与监听重配、CONNECT/WebSocket 升级。证书测试仅使用内存材料，不安装或信任本机证书。

AppKit 隐藏组件检查覆盖开关、第三种启动方式、实际监听配置与二维码、来源列替换、Popover 别名修改与跨行刷新、详情来源与别名回调。以上不等于完整 App 或 iPhone/Android 真机验收。

只捕获经过显式 HTTP 代理的流量；HTTP/2 内容、HTTP/3/UDP、忽略系统代理的 App、蜂窝网络直连不在首版范围。证书绑定或不信任用户 CA 的 App 不能保证 HTTPS 解密。
